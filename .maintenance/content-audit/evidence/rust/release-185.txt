- heading "async closures" [level=3]:
  - code: async
  - text: closures
- paragraph:
  - text: Rust now supports asynchronous closures like
  - code: "async || {}"
  - text: which return futures when called. This works like an
  - code: async fn
  - text: "which can also capture values from the local environment, just like the difference between regular closures and functions. This also comes with 3 analogous traits in the standard library prelude:"
  - code: AsyncFn
  - text: ","
  - code: AsyncFnMut
  - text: ", and"
  - code: AsyncFnOnce
  - text: .
- paragraph:
  - text: In some cases, you could already approximate this with a regular closure and an asynchronous block, like
  - code: "|| async {}"
  - text: . However, the future returned by such an inner block is not able to borrow from the closure captures, but this does work with
  - code: async
  - text: "closures:"
- code:
  - generic: "let mut vec: Vec<String> = vec![];"
  - generic: "let closure = async || {"
  - generic: vec.push(ready(String::from("")).await);
  - generic: "};"
- paragraph:
  - text: It also has not been possible to properly express higher-ranked function signatures with the
  - code: Fn
  - text: traits returning a
  - code: Future
  - text: ", but you can write this with the"
  - code: AsyncFn
  - text: "traits:"
- code:
  - generic: use core::future::Future;
  - generic: "async fn f<Fut>(_: impl for<'a> Fn(&'a u8) -> Fut)"
  - generic: where
  - generic: "Fut: Future<Output = ()>,"
  - generic: "{ todo!() }"
  - generic: "async fn f2(_: impl for<'a> AsyncFn(&'a u8))"
  - generic: "{ todo!() }"
  - generic: "async fn main() {"
  - generic: "async fn g(_: &u8) { todo!() }"
  - generic: f(g).await;
  - generic: //~^ ERROR mismatched types
  - generic: //~| ERROR one type is more general than the other
  - generic: f2(g).await; // ok!
  - generic: "}"
- paragraph:
  - text: So
  - code: async
  - text: closures provide first-class solutions to both of these problems! See
  - link "RFC 3668":
    - /url: https://rust-lang.github.io/rfcs/3668-async-closures.html
  - text: and the
  - link "stabilization report":
    - /url: https://github.com/rust-lang/rust/pull/132706
  - text: for more details.
- heading "Hiding trait implementations from diagnostics" [level=3]
- paragraph:
  - text: The new
  - code: "#[diagnostic::do_not_recommend]"
  - text: "attribute is a hint to the compiler to not show the annotated trait implementation as part of a diagnostic message. For library authors, this is a way to keep the compiler from making suggestions that may be unhelpful or misleading. For example:"
- code:
  - generic: "pub trait Foo {}"
  - generic: "pub trait Bar {}"
  - generic: "impl<T: Foo> Bar for T {}"
  - generic: struct MyType;
  - generic: "fn main() {"
  - generic: "let _object: &dyn Bar = &MyType;"
  - generic: "}"
- code:
  - generic: "error[E0277]: the trait bound `MyType: Bar` is not satisfied"
  - generic: "--> src/main.rs:9:29"
  - generic: "|"
  - generic: "9 | let _object: &dyn Bar = &MyType;"
  - generic: "| ^^^^ the trait `Foo` is not implemented for `MyType`"
  - generic: "|"
  - generic: "note: required for `MyType` to implement `Bar`"
  - generic: "--> src/main.rs:4:14"
  - generic: "|"
  - generic: "4 | impl<T: Foo> Bar for T {}"
  - generic: "| --- ^^^ ^"
  - generic: "| |"
  - generic: "| unsatisfied trait bound introduced here"
  - generic: "= note: required for the cast from `&MyType` to `&dyn Bar`"
- paragraph:
  - text: For some APIs, it might make good sense for you to implement
  - code: Foo
  - text: ", and get"
  - code: Bar
  - text: indirectly by that blanket implementation. For others, it might be expected that most users should implement
  - code: Bar
  - text: directly, so that
  - code: Foo
  - text: "suggestion is a red herring. In that case, adding the diagnostic hint will change the error message like so:"
- code:
  - generic: "#[diagnostic::do_not_recommend]"
  - generic: "impl<T: Foo> Bar for T {}"
- code:
  - generic: "error[E0277]: the trait bound `MyType: Bar` is not satisfied"
  - generic: "--> src/main.rs:10:29"
  - generic: "|"
  - generic: "10 | let _object: &dyn Bar = &MyType;"
  - generic: "| ^^^^ the trait `Bar` is not implemented for `MyType`"
  - generic: "|"
  - generic: "= note: required for the cast from `&MyType` to `&dyn Bar`"
- paragraph:
  - text: See
  - link "RFC 2397":
    - /url: https://rust-lang.github.io/rfcs/2397-do-not-recommend.html
  - text: for the original motivation, and the current
  - link "reference":
    - /url: https://doc.rust-lang.org/reference/attributes/diagnostics.html#the-diagnosticdo_not_recommend-attribute
  - text: for more details.

- heading "Updates to std::env::home_dir()" [level=3]:
  - text: Updates to
  - code: std::env::home_dir()
- paragraph:
  - code: std::env::home_dir()
  - text: has been deprecated for years, because it can give surprising results in some Windows configurations if the
  - code: HOME
  - text: environment variable is set (which is not the normal configuration on Windows).
