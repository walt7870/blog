# 博客内容审查与分阶段改造

审查日期：2026-10-19。范围为当前主工作区 `docs/` 下的 569 篇 Markdown，不代表线上已发布版本。个人页单独检查联系入口。本目录保存维护材料，不作为博客正文或导航入口。

## 审查结论

当前最需要修的是知识准确性、章节之间的因果解释和可验证的案例。缺少图示是重要线索，但不是唯一问题：有的文章超过千行，主要内容仍是打印概念说明的代码；有的旧页面把一致性边界直接当成部署边界。继续统一加长段落或批量放通用流程图，不能解决这些问题。

本次已完成全量结构扫描，精读和人工抽查集中在下文列出的页面；尚未逐篇核验全部技术事实。后续以每批 3–6 篇相关页面推进，先核对机制和版本，再改正文与图，不把扫描通过标成内容合格。

## 每批验收合同

1. 记录原问题、限定改造范围，先核查相邻页和版本；不给未读文章打主观分。
2. 正文说明一个具体场景的输入、运行过程、判断依据、失败结果和验证办法。连续段落解释因果，表格用于对比，代码只保留必要入口。
3. 图与正文共用对象和命名；SVG 放在 `public/<主题>/`，引用为站点绝对路径。源稿保存在本目录 `diagrams/`；先编辑 HTML，再通过 Vue HTML 解析器提取 SVG，导出后复核。
4. 在实际本地中文字体下测量文字边界，检查连线、标签和裁切。浏览器检查桌面、手机、深色与放大视图。原文使用的 Mermaid 准确且可读时可以保留。
5. 用固定输入核对可运行示例，扫描新增资源与链接，执行 `npm run docs:build`。注明构建是否包含其他工作区改动；不把本地验证表述为已发布。
