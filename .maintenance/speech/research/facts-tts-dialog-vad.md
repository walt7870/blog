# Fact sheet: TTS / speech dialogue / VAD (checked 2026-10-28)

How this was checked: each row was read from the official GitHub README, the HF/ModelScope model card, the arXiv abstract, the vendor's docs or changelog, or the GitHub/HF API. "HF created" is the date the HF repo was created (from the HF API). It is close to, but not exactly, the public release date. **UNVERIFIED** marks a value I could not confirm from a primary source. Vendor latency figures are the vendor's own claims, and their measurement conditions differ.

Route key: **AM+Voc** = acoustic model + vocoder; **Codec-LM** = LM over discrete speech/codec tokens with a codec decoder; **LM+Flow** = LLM emits semantic tokens, then flow matching produces mel, then a vocoder; **NAR-Flow/Diff** = non-autoregressive flow matching/diffusion; **AR-Diff** = autoregressive LM plus a per-token diffusion/flow head over continuous latents.

Notes on routes:
- **The 2026 trend:** Qwen3-TTS, MOSS-TTS and Higgs v3 drop the "LM + flow/DiT" second stage and use a pure multi-codebook Codec-LM with a light decoder. VoxCPM and VibeVoice take the AR + diffusion-head route over continuous latents. CosyVoice 3, GLM-TTS and Step-Audio-EditX keep LM+Flow.
- **Non-commercial weights:** F5-TTS, MaskGCT, Spark-TTS, Higgs v3 and Fish S2-Pro. Higgs v2 has a 100k-MAU threshold. IndexTTS uses a custom bilibili license.

## B. Speech LLMs and real-time voice dialogue

Two main designs:
- **Cascaded:** VAD/turn detection → streaming ASR → text LLM → streaming TTS. It is modular, works with any LLM, and supports tool calls easily. It loses paraphrased prosody and emotion, and latency adds up across stages. Examples: Kyutai Unmute, Pipecat/LiveKit pipelines.
- **End-to-end:** a single model takes speech in and produces speech out, sometimes with an interleaved text "inner monologue". Variants:
  - Half-duplex Thinker-Talker (Qwen-Omni).
  - Full-duplex dual-stream (Moshi, GPT-Live).
  - Frozen-LLM + state prediction (Freeze-Omni).
