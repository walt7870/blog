# 稻草小站

一个面向工程实践的技术知识库，使用 VitePress 构建。内容按“可检索、可落地、可排查”的方式组织，覆盖基础协议、Linux、容器、数据库、Java、Rust、架构设计、AI、嵌入式和常用工程工具。

站点不是线性教程，而是一张工程知识地图。入口页负责建立主题全景，细节页负责拆解概念边界、配置入口、典型场景和排错路径。

## 项目结构

```text
.
├── docs/                 # VitePress 正文内容
├── public/               # 静态资源，按主题存放 SVG、图片等
├── .vitepress/           # VitePress 配置、导航、侧边栏和主题扩展
├── index.md              # 站点首页
├── package.json          # 本地开发与构建脚本
└── README.md             # 仓库说明
```

正文内容主要放在 `docs/` 下。静态资源放在项目根目录的 `public/` 下，不放在 `docs/public/`。Markdown 中引用图示时使用站点绝对路径，例如：

```md
![Maven 生命周期与插件执行](/java/maven-lifecycle.svg)
```

## 本地运行

安装依赖：

```bash
npm install
```

启动开发服务：

```bash
npm run docs:dev
```

构建站点：

```bash
npm run docs:build
```

预览构建产物：

```bash
npm run docs:preview
```

## 写作原则

文档默认使用中文记录，技术名词、命令、API、配置项、包名和链接保留原文。正文保持技术知识库口吻，避免任务背景、协作痕迹和营销化表达。

每个专题尽量沉淀为以下结构：

- 概念边界：说明这个技术解决什么问题，不解决什么问题。
- 操作入口：给出配置位置、命令入口、文件位置或关键对象。
- 可复制示例：保留能完成验证闭环的命令、配置或代码片段。
- 典型场景：使用订单、支付、导出、通知、部署、排错、性能优化等真实工程场景解释。
- 排错闭环：说明现象、定位命令、判断标准和修复方向。

涉及容易混淆的流程、层级、生命周期、依赖链、状态流转或请求链路时，优先补充 SVG 图示。图示应服务理解，不做装饰。

## 新增专题流程

新增一个专题时，通常同时处理三件事：

1. 在 `docs/` 下新增入口页和必要的细节页。
2. 在 `public/<topic>/` 下补充图示资源，并在 Markdown 中用站点绝对路径引用。
3. 在 `.vitepress/sidebar.ts` 或 `.vitepress/navbar.ts` 中补充导航入口。

入口页承担导读职责：说明专题解决什么问题、如何阅读、各子页面分别看什么。细节页优先讲清对象关系、生命周期、数据流、配置边界和排查路径。

## 后续创作方向

后续内容建设优先补齐这几类页面：

- 总览页：把零散页面整理成主题地图，补齐阅读路径和核心概念关系。
- 机制页：解释生命周期、数据流、请求链路、依赖解析、运行时边界。
- 实操页：给出最小可用配置、常用命令、验证步骤和故障定位方式。
- 对比页：说明适用场景、不适用场景、选型标准和迁移成本。
- 排错页：按现象组织定位路径，避免只罗列命令。

已有页面做较大改造时，优先保留旧入口可达性，再把正式阅读路径调整到更清晰的新模块。改造完成后检查标题是否空泛、正文是否有生成式口吻、链接和图示路径是否有效。

## 质量检查

提交或发布前执行构建：

```bash
npm run docs:build
```

如果构建失败，需要区分失败点来自本次改动还是工作区已有问题。涉及新增图示时，同时检查文件是否位于 `public/<topic>/`，正文引用路径是否以 `/` 开头，图示尺寸是否适合横向阅读。
