# Linux 进程管理

同一订单服务可能包含HTTP线程、导出子进程和由systemd管理的主进程；宿主机还运行处理设备与内存的内核线程。排查进程要先确定关系和管理边界，再看状态、资源和退出原因。

## 先分清父子与资源归属

![Linux进程创建与管理关系](/linux/process-model.svg)

图中的主机进程树区分PID 1的用户空间服务与kthreadd分支；内核线程并非由systemd派生。线程共享哪些资源、服务cgroup包含哪些进程，则是另一种关系，不能把它们都画成同一种父子箭头。容器内只看到当前PID命名空间可见的进程，编号也可能与主机不同。

| 页面 | 机制与操作入口 |
| --- | --- |
| [systemd](./systemd.md) | unit配置、启动顺序、就绪、重启与停止 |
| [Init进程](./init-process.md) | PID 1、孤儿收养、subreaper与容器信号 |
| [用户进程](./user-processes.md) | 创建、执行、退出与实际waitpid实验 |
| [内核线程](./kernel-threads.md) | 工作队列、软中断、回收及压力证据 |
| [进程命令](../command/process.md) / [速查](../command/process-management.md) | 命令参数、后台任务与优先级 |

观察父子与线程可以使用以下Linux procps命令；进程很多时按目标PID缩小范围：

```bash
ps -eo pid,ppid,stat,comm --forest
ps -L -p 目标PID -o pid,ppid,lwp,stat,pcpu,comm
cat /proc/目标PID/cgroup
```

PPID回答谁是当前父进程，LWP展示线程ID，cgroup回答部分资源和管理归属。三者不能互相替代。例如服务fork出多个worker，主进程退出不表示worker已经被回收，服务停止时还要看管理器的进程组/cgroup策略。

## 状态是快照

![Linux进程状态与退出回收](/linux/process-state-flow.svg)

| 状态 | 表示什么 | 需要补充什么证据 |
| --- | --- | --- |
| R | 正在运行或可运行 | CPU、配额、线程热点 |
| S | 可中断等待 | 等待事件、定时器、锁或系统调用 |
| D | 不可中断类等待 | wchan、内核栈、设备与I/O延迟 |
| T / t | 作业停止 / 跟踪停止 | 信号、调试器与管理动作 |
| Z | 已退出但尚有待回收状态 | PPID及wait处理 |
| I | 空闲内核线程，依版本可见 | 不应直接视为异常 |

图是常见路径，省略部分内核状态与异步信号转换。唤醒不意味着立即获得CPU；Z不能恢复成运行任务。D常和I/O有关，但不是“磁盘坏了”的证明；SIGKILL是否能及时结束还要看具体内核等待。细节与实验见 [用户进程](./user-processes.md)。

## 用订单故障串联资源

导出服务耗时上升，先把慢请求时间与进程证据对齐。线程栈显示等待数据库，先看查询与连接；用户态CPU占满时看代码采样；D等待与磁盘延迟同步上升时，再查块设备或远程文件系统。不要先换调度参数或清空缓存。

| 资源 | 观察入口 | 不能直接等同的概念 |
| --- | --- | --- |
| CPU | top、pidstat、线程采样 | 负载平均值与CPU利用率 |
| 内存 | status、smaps、PSI、cgroup | RSS与独占内存、主机空闲与容器限额 |
| I/O | iostat、pidstat -d、内核日志 | 吞吐大与延迟高 |
| 文件描述符 | lsof、fd目录、limits | 文件数量与打开句柄数量 |
| 网络 | ss、队列与应用超时日志 | 端口监听与请求成功 |

工具可能需要sysstat等软件包与访问权限。应使用有限采样窗口，保留起止时间；一张top截图不能说明持续趋势。

## 失败后如何闭环

服务未启动时，先看 `systemctl status` 的 Result、退出码与本次启动日志，再核对有效unit、执行路径、身份和目录；出现重启限流时保留首次失败，不先增大次数。

进程存在但服务慢时，先按同一时间窗收集状态、线程和资源，定位等待来源。僵尸增多则先找父进程：

```bash
ps -eo stat,ppid,pid,comm | awk '$1 ~ /^Z/'
```

修复后用同一输入验证结果、延迟、资源与子进程数。涉及停止或重启时，还应核对在途请求和任务最终状态；“PID变了”只证明发生了管理动作。
