# Linux 系统概览

订单接口突然超时，可能是应用等数据库，也可能是磁盘、内存或网络出了问题。Linux 提供进程、文件、网络和资源管理机制；发行版把内核、系统库、工具、软件包和服务管理器组合成可维护的系统。排查时先找到请求经过哪些组件，再确定在哪一层取证。

## 服务如何使用系统

![Linux订单服务与内核资源的关系](/linux/linux-runtime-boundaries.svg)

Nginx 接收连接后把请求转给订单进程，订单进程通过系统调用使用套接字、文件和内存。应用也会执行不涉及系统调用的计算；系统库并不等于内核，容器镜像也不带一个独立运行的 Linux 内核。

例如订单导出慢：数据库查询已经耗时 9 秒时，应先查查询和下游；进程不断读写本地临时文件且磁盘延迟上升时，再沿 I/O 链路分析。仅看“CPU 不高”不能排除系统瓶颈。

| --- | --- | --- |

## 先确认自己在哪个环境

以下命令用于 Linux；macOS 的 `ps` 参数和文件布局不同，不能直接套用。

```bash
cat /etc/os-release
uname -r
ps -p 1 -o pid,comm,args
id
pwd
```

`os-release` 描述发行版用户空间，`uname -r` 描述正在运行的内核。容器里可能显示 Debian，而内核属于宿主机或 Docker Desktop 的 Linux 虚拟机；PID 1 也可能只是应用或轻量 init。没有 systemd 作为服务管理器时，不能靠 `systemctl` 管理容器主进程。

路径还受挂载和命名空间影响：容器的 `/var/log` 不一定对应宿主机同名目录。先确定当前身份、工作目录和挂载对象，再判断权限或容量，避免在错误环境修改文件。

## 发行版如何选

| 系列 | 常见软件包入口 | 选择时核对 |
| --- | --- | --- |
| Debian / Ubuntu | APT、dpkg、deb | 具体版本支持期、目标软件与云镜像 |
| RHEL / Fedora / Rocky / AlmaLinux | DNF、RPM | 产品定位、ABI、认证与订阅范围 |
| SUSE / openSUSE | Zypper、RPM | 固定或滚动发布、具体产品支持合同 |
| Arch | pacman | 持续升级与回归维护能力 |
| Alpine | apk、musl libc | 程序的 libc、动态链接器与工具兼容性 |

不能用“某系列默认更快、更安全”替代验证。CentOS Stream 与停止维护的 CentOS Linux 是不同产品；LTS 标签也不表示所有软件包都有相同维护期限。小镜像可减少携带的软件，但不会自动消除漏洞或配置错误。

例如一个只提供 glibc 二进制库的语音服务，迁移到 Alpine 前要验证 musl 兼容性。纯静态程序或有匹配构建的程序可能适用；不能仅根据镜像下载体积决定基础系统。包管理器的历史回退也不是数据库数据、外部配置与内核的整体回滚。

## 文件、权限和资源边界

配置一般在 `/etc`，运行时状态常在 `/run`，可变业务数据或日志常在 `/var`；实际位置以服务配置为准。`/proc` 和 `/sys` 提供内核视图，不能当成普通磁盘目录清理。部分发行版的 `/bin`、`/sbin` 是指向 `/usr` 下目录的符号链接。

服务读不到配置时，要同时看文件所有者、目录遍历权限、运行身份，以及 SELinux/AppArmor 等额外限制；`chmod 777` 不是定位原因的办法。UID 分配范围由发行版策略决定，不固定为所有系统的 1–999 和 1000 起。

内存也有多层视角：主机尚有可用内存，服务仍可能触发 cgroup 限额；RSS 不等于独占物理内存。负载平均值包含可运行任务及不可中断等待，不能直接当 CPU 利用率。详细观察入口见 [系统监控](./command/system-monitoring.md)。

## 以订单故障建立排查闭环

| 现象 | 先取证 | 再判断 |
| --- | --- | --- |
| 进程没起来 | unit、退出码、当前启动日志 | 路径、身份、配置或重启限流 |
| 进程在但接口不通 | 监听地址、端口、路由、代理响应 | 本机服务、转发链或远端依赖 |
| CPU 或延迟升高 | 同时间窗线程、请求和资源采样 | 计算、锁等待、I/O 或配额竞争 |
| 磁盘满 | 挂载点、inode、大目录、已删仍打开文件 | 容量、文件数量或句柄持有 |
| 收到终止信号却不退出 | 进程树、信号处理、停止超时 | 应用清理、子进程或内核等待 |

每次改动后用同一请求复验正确性、延迟和资源，保留修改前后的时间窗口。先会定位一条服务链，再深入内核、性能和部署专题，比记住大量发行版与工具名称更有用。
