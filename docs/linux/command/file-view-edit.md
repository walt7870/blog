# 文件查看与编辑

查看配置文件和排查日志需要的读法不同。配置通常较小，可以通读；几 GB 的日志应先限定时间、行数或请求编号，再看上下文。选对读取方式，能避免终端被刷屏，也能保留定位问题所需的前后关系。

![从文件类型选择读取方式，再按请求编号定位上下文](/linux/log-reading-path.svg)

## 先选择读取方式

| 当前任务 | 命令入口 | 判断依据 |
| --- | --- | --- |
| 查看短配置、拼接少量文件 | `cat app.conf` | 确认文件足够小，输出可完整阅读 |
| 阅读大文件并来回搜索 | `less app.log` | 分页查看，不把整份内容刷入终端 |
| 确认 CSV 表头或文件开头 | `head -n 5 customers.csv` | 只需要头部少量内容 |
| 查看最近错误 | `tail -n 100 app.log` | 问题刚发生，先看末尾 |
| 跟踪持续写入的日志 | `tail -n 50 -F app.log` | 日志可能轮转或被重建，需要按文件名重新跟踪 |
| 引用某段配置的准确行号 | `nl -ba app.conf` | 包括空行一起编号，方便沟通和复核 |

`tail -f` 通常跟随已经打开的文件描述符，文件被重命名轮转后可能继续看旧文件。GNU `tail -F` 等价于按名称跟随并持续重试，更适合常见的“重命名旧日志、创建同名新日志”场景。输出停止也可能是应用没有继续写入，不能仅凭终端安静判断服务正常。

## 例子：导出订单失败，怎样找到前因后果

假设服务日志写在 `app.log`，一次导出任务的请求编号为 `req-2048`。先看末尾，确认错误时间和请求编号；再搜索这个编号，读取匹配行前后内容，检查是否先出现数据库超时、文件写入失败或上游重试。

```bash
tail -n 80 app.log
grep -n -F -C 4 'req-2048' app.log
less -N app.log
```

在 `less` 中输入 `/req-2048` 搜索，按 `n` 跳到下一处、`N` 回到上一处，按 `q` 退出。`-N` 显示原文件行号。日志持续增长时，可以先在另一终端运行 `tail -n 50 -F app.log` 观察新请求，按 `Ctrl-C` 停止跟踪。

请求编号比只搜索 `ERROR` 更有帮助：一条请求的前置告警、重试和最终结果可能分散在多行，而且并非每一行都含有错误级别。已经知道目标在第 120 到 150 行时，可只输出这一段：

```bash
sed -n '120,150p' app.log
```

这限制了输出范围，但 `sed` 并不是日志索引系统。文件很大且要反复按时间和多个字段检索时，应考虑应用已有的集中日志平台。文件位置还没找到时，先到 [文件查找](./file-search)；需要提取字段或统计错误数量时，转到 [文本处理](./text-processing)。

## 修改配置时保留验证闭环

先确认正在修改的是服务实际加载的配置。备份后使用 `vim` 或 `nano` 编辑，再比较改动，调用服务自身的语法检查，最后才加载。备份文件放在服务不会扫描的目录，避免带扩展名的备份也被 `include` 规则读入。

下面以已经存在的本地工作文件 `app.conf` 为例，备份目录由 `mktemp` 创建：

```bash
config_backup_dir=$(mktemp -d)
cp -p app.conf "$config_backup_dir/app.conf"
vim app.conf
diff -u "$config_backup_dir/app.conf" app.conf
```

`diff` 返回 1 表示文件存在差异，不代表命令出错。随后运行相应服务的检查命令，例如 Nginx 的 `nginx -t`。语法检查只能发现配置格式和部分引用问题；加载后还要核对服务日志、状态和真实请求，确认新配置生效。如果结果异常，恢复原配置并重新检查与加载。Vim 的模式和编辑动作见 [Vim 指南](/docs/tools/vim/)，这里不重复列快捷键。

## 常见误判

`Permission denied` 表示当前身份无权读取，应先核对文件所有者、权限和运维授权，不能用放开全局权限解决。二进制文件不适合直接 `cat`，可以先用 `file` 判断类型。`cat file > file` 会在读取前截断文件，不能用来原地处理数据；需要替换文件时，应写入临时文件，验证结果后再替换。

对于日志，先定位时间和请求，再解释状态；对于配置，先比较和检查，再验证加载结果。命令执行成功与问题已经解决，是两个不同的验收点。
