# 文件基础操作

一次订单导出会产生临时文件、最终CSV和下载链接。复制文件、给文件改名、增加硬链接、创建符号链接，改变的是不同对象；分清路径、目录项和inode，才能解释“原文件删了为什么空间还在”或“链接为什么失效”。

以下使用Linux/GNU工具与Bash。练习在新建临时目录中进行；示例目录保留供观察，不修改真实业务数据。

## 路径、目录项和文件内容

![硬链接共享inode，符号链接保存路径，打开句柄可延长文件存活](/linux/file-name-inode.svg)

路径中的目录项把名称关联到inode，inode再关联元数据和内容。硬链接是同一文件的另一个名称，没有永久特殊的“原名”；符号链接本身是独立对象，保存目标路径。相对符号链接从链接所在目录解析，不是从当前终端目录解析。

```bash
file_lab_dir=$(mktemp -d)
cd -- "$file_lab_dir"
mkdir -p -- source archive
printf 'order_id,total\n2048,5970\n' > source/orders.csv
ln -- source/orders.csv source/orders-hard.csv
ln -s -- orders.csv source/orders-link.csv
stat -c '%i %h %s %n' -- source/orders.csv source/orders-hard.csv
readlink -- source/orders-link.csv
```

两个普通文件名的inode相同，链接数为2；软链接保存orders.csv。对目录通常不能创建硬链接，硬链接也不能跨文件系统。读取链接目标用 `stat -L`，观察链接本身用默认stat；不要把两种输出混在一起比较。

## 目录与当前工作位置

| 目的 | 入口 | 容易混淆的地方 |
| --- | --- | --- |
| 查看当前位置 | `pwd -L`、`pwd -P` | 逻辑路径可包含符号链接，物理路径解析链接 |
| 切换目录 | `cd 路径`、`cd -` | cd是shell内建，子进程不能改变父shell目录 |
| 列目录内容 | `ls -la -- 路径` | -a包含隐藏项，普通*默认不含隐藏项 |
| 看目录自身 | `ls -ld -- 路径` | 与列出目录内部不同 |
| 建目录 | `mkdir -p -- a/b` | -p允许已有目录，不验证其权限是否符合要求 |
| 删空目录 | `rmdir -- 空目录` | 非空失败是保护信息，不应直接升级为递归清理 |

Bash的 `{src,docs}` 是大括号扩展，`*.csv` 是文件名匹配。默认未匹配的glob可能原样传给命令；批量脚本需明确空结果行为，不能假设每个shell都有相同选项。

## 复制和移动的结果不同

```bash
cp -a -- source/. archive/
mv -- source/orders.csv source/orders-final.csv
cat -- source/orders-hard.csv
test -L source/orders-link.csv && test ! -e source/orders-link.csv
```

复制后archive保存一组独立副本，GNU cp -a会尽量保留属性和内部硬链接关系，但不构成应用一致性快照。源目录尾部的 `/.` 表示复制内部内容，包含隐藏项；目标是否已存在会影响最终目录层级，执行后应核对。

改名后，hard文件仍能读取，原软链接因目标名消失而断开。若移动的是链接本身，它保存的相对路径不自动调整，换目录后可能指向另一个目标。

同一文件系统内mv通常通过rename改变目录项，不复制整份内容；跨文件系统时需要复制后删除，不具有同样的原子切换边界。即使同盘rename可原子替换名称，也不等于数据已持久化，更不等于多个文件或数据库事务一起提交。

| 选项 | 准确含义 |
| --- | --- |
| `cp -p` | 尝试保留模式、所有者和时间，受权限与文件系统约束 |
| `cp -a` | GNU归档模式，递归并尽量保留链接和属性 |
| `cp -v` | 输出处理的文件名，不显示单个大文件的字节进度 |
| `cp -i` / `mv -i` | 覆盖前询问，自动化需明确交互是否可用 |
| `cp -f` | 目标无法打开时尝试移除再创建，不是通用“不询问”开关 |
| `mv -n` | 不覆盖现存目标；跳过未必返回错误，需核对结果 |

需要进度可使用具备进度选项的rsync；需要快照或可靠备份，应同时考虑并发写入、元数据、恢复验证和数据库一致性。

## 删除的是名称，空间何时释放

```bash
rm -- source/orders-hard.csv
ls -li -- source/
```

这只移除一个目录项，final文件仍在。最后一个硬链接被移除后，若进程仍持有打开句柄，内容仍可能占用空间。真正释放还取决于引用与文件系统机制；快照、写时复制和稀疏文件也会影响空间读数。

删除符号链接通常不删除目标；对链接路径添加尾部斜杠会改变路径解析，不要用于“只删链接”。`--preserve-root` 也只提供特定根目录保护，不会阻止删除错误业务目录。

## 批量操作先保留文件名边界

把目录树拍平复制到同一目标，两个子目录中的orders.csv可能互相覆盖。按层级备份时优先使用目录复制或rsync；只有明确允许拍平并处理重名时才这样做。

```bash
find source -type f -name '*.csv' -print
find source -type f -name '*.csv' -exec stat -c '%s %n' -- {} +
```

`-exec ... {} +` 直接传递参数，可保留空格和换行文件名。换成xargs时要配合 `-print0` 和 `-0`，并明确空输入行为。并发执行不会解决目标重名、I/O瓶颈或事务一致性。

## 按错误定位

权限拒绝先查身份、父目录和目标权限；空间不足先区分容量与inode；文件不存在先核对pwd、大小写和符号链接；目录非空先看隐藏项与实际内容。命令页不提供“清空全部临时文件”的兜底方案。

复验时检查路径、文件数量、大小、内容摘要及使用者是否符合预期。日志读取见 [文件查看](./file-view-edit.md)，按条件定位见 [文件查找](./file-search.md)，访问规则见 [文件权限](./file-permissions.md)。
