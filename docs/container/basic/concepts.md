# 容器核心概念

用同一镜像启动两个订单导出容器，它们拥有相同的初始程序文件，却不会自动共享后来生成的 CSV。镜像描述交付内容，容器拥有自己的进程和运行状态，文件能否共享取决于实际挂载与外部存储。

![两个容器复用镜像但拥有独立写入与进程的关系](/container/container-isolation-model.svg)

## 镜像与实例的生命周期

OCI 镜像由清单、配置及文件系统层等对象组成；多平台镜像索引还可以引用不同平台的清单。镜像中的程序和用户态库不会替代宿主内核，Linux 镜像仍需要合适的 Linux 运行环境。CPU 架构、系统调用、设备与驱动需求也必须匹配。

创建容器会建立实例配置和相关运行资源，启动才会运行进程。停止进程不等于删除实例，删除实例也不等于删除原镜像。以 Docker 的普通容器为例，停止后再启动原实例，原可写层通常保留；删除并重建时，新实例从镜像和新的运行配置开始。

标签是可移动的名字，今天的 `orders:stable` 可能与明天不同。摘要标识具体内容对象，发布时记录镜像摘要有利于追踪；多平台索引摘要与平台清单摘要属于不同对象，排错时还要记录实际运行平台。摘要相同能说明对应内容相同，不能单独证明来源可信或漏洞已修复。

## 写入究竟落在哪里

未被其他挂载覆盖的镜像路径，写入通常进入容器可写层。给 `/exports` 挂载卷后，写入就转向卷；挂载还会遮住镜像中原有的同名路径。因此“容器内看到的文件”不能直接等同于“镜像自带的文件”。

| 数据位置 | 生命周期与使用约束 |
| --- | --- |
| 镜像层 | 交付程序和依赖；运行实例不会原地修改发布镜像 |
| 容器可写层 | 跟随实例；适合可重建临时内容，不承担长期业务数据 |
| 命名卷或绑定挂载 | 由卷对象或宿主路径管理；需另行规划权限、清理与备份 |
| tmpfs 挂载 | 内存临时数据；不作为持久化结果，仍消耗运行资源 |
| 数据库、对象或共享存储 | 由外部服务管理；应用需要处理鉴权、失败和一致性 |

订单导出结果需要下载和审计，就应明确保存期限与备份方案。保留卷只能避免数据随容器可写层删除，不能防止误删、损坏或宿主磁盘故障。多个实例同时写同一卷时，还要确认存储支持的访问模式与应用并发语义。

## 视图隔离与资源约束

Linux namespace 控制进程能看见的 PID、挂载点、网络等视图；它们可以按配置共享。Kubernetes 同一个 Pod 内的容器通常共享网络 namespace，使用宿主网络的容器也不会得到独立的容器网络视图。不能仅凭“在容器里”推断所有 namespace 都独立。

cgroup 用于资源统计与控制。CPU 配额限制的是可用 CPU 时间，达到配额可能发生节流，并非预留独占核心；内存达到约束时可能触发 OOM 终止。是否有权限、设备和系统调用限制，还要看用户身份、capability、seccomp、LSM 等配置。把宿主 Docker socket 暴露给不可信进程，会越过原本希望建立的管理边界。

Linux 容器共享所在 Linux 环境的内核；macOS 上的 Linux 容器通常运行在虚拟机中，共享的是虚拟机内核。容器与虚拟机可以组合使用。

## 观察一个临时实例

在已安装 Docker 且能够拉取镜像的实验环境中运行：

```bash
docker run --rm public.ecr.aws/docker/library/alpine:3.22 sh -c '
  uname -s
  printf "pid1: "; tr "\000" " " < /proc/1/cmdline; printf "\n"
  cat /proc/self/cgroup
  ls -l /proc/self/ns
'
```

这里观察的是内核类型、PID 视图、cgroup 路径与 namespace 标识。`--rm` 会在进程退出后删除这个临时实例。cgroup namespace 下可能只显示 `0::/`，这不证明宿主没有设置限制；还需结合运行配置与对应控制文件检查。该命令只用于观察，也不能当作隔离强度或业务容量测试。
