# 开发方法

从需求探索到代码验证、发布运行，开发方法解决的是不同阶段的反馈问题。敏捷、TDD、DevOps 和 AI 编程可以组合使用：先找到当前缺少的证据，再决定下一步。

## 从当前问题开始

需求不清先试用，规则明确后再实现，发布后继续收集运行反馈。下面三个阶段分别连接对应的方法与工程实践。

## 例子：给记账应用加账单导出

小王说“我想把账单导出来”，但还没确定文件用途、字段和时间范围。把这项需求拆成四步，每一步都有可检查的结果。

1. **先试用**：用测试账单做“最近 7 天 CSV”原型。试用后才发现，真正需要的是按月对账，而且不能出现银行卡号。这里适合原型探索与 Vibe Coding。
2. **定规则**：写清账户权限、字段白名单、文件有效期和失败重试。用 BDD 示例或契约测试明确“其他账户不能下载”。
3. **小批次实现**：先完成一个月 CSV，再增加异步任务和历史记录。手写或交给 Agent 都要检查差异、测试和实际文件。
4. **灰度交付**：用同一份构建制品逐步开放。数据库压力异常就停止放量、恢复服务，再补充性能验证。
