# iOS 应用架构与交付

iOS 是 iPhone 的操作系统，iPad 使用 iPadOS，两者共享大量开发技术，但需要分别确认系统版本与 API 可用性。SwiftUI 和 UIKit 用于构建应用界面；AppKit 属于 macOS，不能当作 iOS 的 UI 框架。系统采用 XNU 内核，但应用开发通常通过受支持的 SDK 访问能力，而不是直接依赖内核内部结构。

以“拍摄收据并上传”为例，界面负责预览和反馈，应用逻辑管理拍摄与上传任务，AVFoundation 或照片选择组件提供输入，URLSession 处理网络传输，沙盒保存文件。相机权限、应用退到后台、进程被系统终止和网络断开都会影响链路，不能只把页面画好就认为业务完整。

## SDK 能力与应用职责

| 入口 | 常用能力 | 设计边界 |
| --- | --- | --- |
| SwiftUI / UIKit | 界面、导航、手势、无障碍 | UI 更新遵守线程与 actor 隔离约束，避免主线程执行图片解码与阻塞 I/O |
| Foundation / URLSession | 文件、数据编码、网络会话 | 网络成功、服务器业务提交和本地记录成功是不同结果 |
| AVFoundation / PhotosUI | 拍摄、媒体处理、照片选择 | 按实际 API 请求权限；系统照片选择器与直接访问整个照片库的权限不同 |
| 持久化与安全服务 | 文件、Core Data、SwiftData、Keychain | UserDefaults 适合偏好设置，令牌等敏感凭据按用途使用 Keychain |
| BackgroundTasks / 后台 URLSession | 系统调度任务、符合条件的文件传输 | 系统控制执行时机与资源，不承诺应用任意时刻常驻 |

这些框架按任务协作，不是每次请求都必须依次穿过的固定四层。Core Data 是对象图与持久化框架，不等于数据库；SwiftData 需要核对部署目标和模型迁移能力；Metal 用于底层 GPU 编程，已弃用的 OpenGL ES 不宜作为新项目默认方案。

## 项目与签名从哪里配置

在 Xcode 的 Target 中核对 `Bundle Identifier`、`Signing & Capabilities`、最低部署版本和支持设备；在构建设置确认 SDK、配置、架构与依赖。SwiftUI 的 `App` 入口和 UIKit 的委托、scene 生命周期可以有不同组织方式，不要求每个项目同时拥有同一组文件。

```sh
xcodebuild -list -project ReceiptApp.xcodeproj
xcodebuild -showBuildSettings -project ReceiptApp.xcodeproj -scheme ReceiptApp
```

命令中的项目和 scheme 是示例，需要替换为实际名称；使用 workspace 的项目改用 `-workspace`。输出用于确认构建目标与设置，不代表已签名、已通过真机测试或可以发布。开发机需安装与项目匹配的 Xcode，并完成所需平台组件和账号配置。

依赖可以通过 Swift Package Manager 或项目已有工具管理。引入二进制依赖时分别核对设备与模拟器平台、架构切片和最低系统版本；两边都叫 `arm64` 也不是同一构建平台。可用 XCFramework 封装多个目标变体，但包内仍必须实际包含所需变体。

## 上传任务必须可恢复

用户确认收据后，先把待上传文件和稳定任务标识保存到应用可控的位置，再创建网络任务。服务端按账号、任务标识与文件内容约束处理重复请求，客户端将业务确认写回本地。上传进度达到 100% 只说明传输进度，不能代替服务端提交成功的响应。

如果应用退到后台后还需要传输文件，可以评估后台 URLSession；系统负责调度传输，应用需持久化会话与业务任务的对应关系，并处理重新唤醒后的回调。BackgroundTasks 中用于刷新和延后处理的任务由系统择机安排，不是精确定时器；其他任务类型需按其具体调度合同设计。用户强制退出、系统终止、网络策略与设备状态的行为不同，不能承诺“进程结束后一定继续上传”。

进程重启后，读取未完成任务并与传输会话或服务端状态核对。服务器已收下文件、客户端还没登记时，应通过稳定标识找回结果；重新拍摄产生的新任务也不能被旧回调覆盖。涉及付款、报销入账等远端副作用时，网络重试仍需由服务端幂等合同保护。

## 权限、数据与发布

只在使用相应能力时请求权限，配置准确的用途说明，并为拒绝、受限与授权后撤销提供可理解的状态。文件保存位置要符合是否允许重建、备份和共享的要求；敏感数据还需确定文件保护等级、Keychain 访问条件和日志内容。沙盒隔离不代表凭据可以明文记录。

发布前通过 Archive 检查签名、entitlements、版本与构建号，选择适用的分发渠道。TestFlight 可用于测试分发，正式发布还需处理 App Store Connect 元数据、隐私声明、第三方 SDK 与审核要求；具体规则会变化，应按提交时的要求核对。UI 框架或应用架构名称不会自动满足这些条件。

## 验证与排错

收据功能至少覆盖拒绝权限、低存储空间、上传中断网、退后台、系统回收后重启和重复点击。先区分 UI 状态、系统传输状态与服务器业务状态，再沿稳定任务标识核对，不把它们压成一个 `isUploading` 布尔值。

真机验证相机、后台传输、内存压力与签名能力；模拟器用于方便地覆盖布局、部分逻辑与系统版本组合。启动失败查设备控制台与签名，卡顿用 Instruments 定位主线程阻塞，内存异常检查大图解码、对象持有与并发数。发布包还需验证旧数据迁移及失败后重试，Debug 下成功不能替代 Release 验收。
