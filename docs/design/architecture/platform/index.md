# 开发平台与兼容性

开发平台是程序编译、运行和交付所依赖的环境。它包括操作系统及其 API、处理器指令集、二进制接口、运行时、系统库和发布规则。“都用 C++”“都是 Linux”或“已经装进容器”只确认了其中一部分，不能证明同一份产物可以直接运行。

例如在 Linux x86-64 上编译一个图片处理工具，把它复制到 Linux arm64 机器，内核可能报 `Exec format error`；重新编译成 arm64 后，又可能因动态加载器、glibc 版本或第三方图像库不匹配而失败。平台选择首先要明确交付目标，再选择能满足这些条件的开发工具。

## 先分清五类约束

| 约束 | 要确认的内容 | 常见误判 |
| --- | --- | --- |
| 操作系统与 API | Linux、Windows、Android、iOS 的系统能力、权限与生命周期 | 同为 ARM 的 Android 库直接给 iOS 使用 |
| 指令集与扩展 | x86-64、AArch64，最低 CPU 特性 | 在新 CPU 上启用 AVX2 后认为所有 x86-64 都能运行 |
| ABI 与系统库 | 调用约定、对象格式、加载器、libc、C++ 运行库 | 只检查文件名中的 `arm64` |
| 运行时与依赖 | JVM、Python、.NET、浏览器及原生扩展的支持范围 | Java/Python 源码可移植，就认为 JNI 和 wheel 也自动通用 |
| 交付与设备合同 | 签名、权限、最低系统版本、驱动、商店或企业分发 | 模拟器成功等于真机和发布包都通过 |

这些条件是交叉约束，不是固定从上到下调用的五层架构。一个纯 Java 程序可由目标 JVM 解释或编译执行，但仍受 JVM 版本、文件路径、系统行为和原生依赖限制；浏览器应用也需要核对功能 API、媒体格式、权限和离线行为。

## 各平台分别看什么

服务端先读 [Linux x86-64](./linux-x86.md) 的系统与部署入口，再读 [Linux ARM](./linux-arm.md) 的指令集、sysroot 与迁移验证。选择服务器 CPU 时，比较实际负载的吞吐、延迟、内存、软件支持、单价和能耗，不能用 RISC/CISC 标签直接推导成本或性能。

桌面程序读 [Windows](./windows.md)，关注应用模型、运行库、权限、安装升级和设备驱动。移动程序分别读 [Android](./android.md) 的构建工具、ABI 和系统生命周期，以及 [iOS](./ios.md) 的 SDK、签名、沙盒与后台执行。平台偏好应来自目标用户使用的设备、外设和分发条件，不以“用户价值高低”替代需求分析。

需要浏览器交付时看[前端开发](../../../devlanguage/front/index.md)，需要统一服务端依赖时看[容器专题](../../../container/index.md)。跨平台框架能够复用部分界面和业务代码；推送、支付、摄像头、文件系统和无障碍通常仍要做平台适配，并分别验收。

## 容器解决到哪一层

容器镜像包含用户空间文件及启动配置，运行时仍使用宿主内核提供的能力。Linux 容器不能仅凭镜像就在原生 Windows 内核上运行；桌面容器工具可以借助 Linux 虚拟机提供环境，这不等于抹掉内核差异。`linux/amd64` 与 `linux/arm64` 的镜像通常包含不同的可执行文件，多架构清单负责为目标选择对应镜像，并不会把现有二进制转换成另一指令集。

模拟执行可以辅助构建与测试，但不能替代目标设备上的驱动、CPU 扩展、性能和长时间稳定性验收。GPU、音频设备、内核模块与硬件授权还需要核对宿主侧能力及挂载、权限等运行条件。

## 用图片处理服务做选型

假设服务接收图片并生成缩略图，现有版本运行在 Linux x86-64，计划加入 arm64 节点。先列出解码库、字体、原生 Python 扩展、镜像基础系统和可选 GPU 插件，核对它们是否有目标版本。选择缺失依赖的替代或构建方案后，分别生成镜像，使用同一组正常图片、损坏图片、大尺寸图片与并发请求比较输出和资源占用。

如果程序能启动却在处理 JPEG 时崩溃，优先定位首次加载的原生库及其 ABI；如果结果相同但延迟上升，检查是否误用了模拟执行、失去 SIMD 路径或改变了线程数。架构迁移的验收结果应同时包含目标机器、软件版本、输入集、输出差异和性能范围，不能只记录“镜像构建成功”。

## 排查入口

遇到无法运行，先记录目标系统、架构、产物格式与错误原文。`Exec format error` 检查对象格式与架构；文件明明存在却报找不到，检查脚本解释器或动态加载器；缺少符号检查依赖版本与加载顺序；启动后权限失败检查系统授权、目录和设备访问。各平台详细页提供对应命令与工具，本页负责确定该往哪一层继续查。
