# 声学与语音导读

这个系列讲一台能听会说的设备从头到尾要经过什么：声音怎样被采集和播放，怎样去掉回声和噪声，怎样识别文字、区分说话人、合成回答，模型怎样放到本地设备上运行，最后整条链路怎样评估和选型。声学和语音分不开：一只麦克风、一个扬声器的问题，最后都会表现为识别错、唤不醒。

在智能音箱、会议终端、车载座舱、耳机、机器人、语音遥控器、客服系统里，声学问题通常表现为“听不清、唤不醒、识别错、播放刺耳、回声大、噪声重、远场效果差”。这些问题不能只靠模型解决，也不能只靠结构件解决，需要把声场、硬件、信号处理和语音算法放在一条链路里看。

## 一条典型语音链路

![语音交互流水线](/acoustics/speech-pipeline.svg)

语音链路可以按输入、处理、理解、输出四段理解：

1. 输入：麦克风把空气压力变化转成电信号，再经过 ADC 变成 PCM 数据。
2. 处理：前处理模块压制回声、噪声和音量波动，必要时使用麦克风阵列增强目标方向。
3. 理解：唤醒模块判断是否进入交互，ASR 把语音转成文本，NLU 或大模型理解意图。
4. 输出：TTS 把文本转成音频，经过 DAC、功放和扬声器播放，播放参考信号再回送给 AEC。

## 核心边界

### 声学与音频

声学更关注声音在物理空间中的产生、传播和感知，音频更关注声音信号的采集、编码、传输、处理和播放。工程项目里两者经常交叠：麦克风开孔、喇叭腔体、回声路径属于声学问题；采样率、PCM、滤波、编码属于音频问题。

### 语音与普通音频

语音是音频的一类，但语音系统有更明确的任务目标：听清人说话、判断是否有人说话、识别文字、理解命令、合成回答。音乐播放更重视频响、失真、动态和主观听感；语音交互更重视 SNR、唤醒率、识别率、端到端延迟和复杂环境鲁棒性。

### 算法问题与结构问题

结构问题会直接改变算法输入。例如麦克风孔被遮挡、密封不良、喇叭漏音到麦克风、阵列间距不准，都会让算法拿到错误信号。算法能缓解噪声和回声，但无法完全补救错误的声学结构。

## 两种读法

**按顺序读**：适合第一次接触语音系统。每篇结尾都指向下一篇。

**按问题读**：手上已经有设备或服务，从现象对应的场景切入：

| 场景 | 优先关注 | 典型风险 | 先读 |
| --- | --- | --- | --- |
| 智能音箱远场唤醒 | 麦克风阵列、AEC、波束形成、唤醒阈值 | 播放音乐时唤不醒、远距离漏唤醒 | 02、04、07 |
| 会议终端与会议转写 | 多人拾音、回声消除、双讲、说话人分离 | 对方听到回声、文字归错人 | 04、10、16 |
| 车载语音 | 路噪、风噪、座舱反射、多人位置 | 高速行驶识别率下降、误唤醒 | 04、07、17 |
| 耳机通话 | 近嘴拾音、风噪、骨传导、低功耗 | 户外风噪大、语音发闷 | 02、04 |
| 语音助手与大模型对话 | 流式识别、轮次判断、流式合成、打断 | 响应慢、抢话、打断不了 | 05、11、15 |
| 客服录音质检 | 双声道分离、长音频切段、ASR 后处理 | 采样率低、压缩损伤、口音和噪声 | 08、09、13 |
| 离线或端侧识别 | 模型体积、内存、RTF、包体 | 设备跑不动、模型许可证不允许 | 09、12、14 |

各类指标（SNR、ERLE、WER、误唤醒次数/小时、MOS、端到端延迟）的定义和计算口径集中在 [16. 质量评估与排错](./quality-evaluation.md)。

## 总结
