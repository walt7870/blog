# 前端框架与工具生态

前端框架生态可以分为四层：组件框架负责组织页面和交互，元框架负责路由、渲染模式和服务端能力，跨端框架负责多运行端交付，构建工具负责开发服务器、打包和资源处理。把这些概念混在一起比较，容易导致选型失焦。

例如商品页用 Vue 组织数量与库存提示，用 Nuxt 组织路由和服务器渲染，用构建工具生成资源，最后交给对应运行环境。它们可以同时出现在一个项目里，并不是四个互斥选项。手机 App 则要另行判断原生控件、平台插件与商店交付，不能把网页构建结果当作已适配 App。

## 选型路线

后台和业务系统先检查现有团队、组件资产与维护周期，再比较 React、Vue、Angular 或 Svelte 的状态模型和应用方案。用同一条“列表查询 → 编辑草稿 → 保存冲突 → 刷新恢复”业务做验证，比仅凭流行度或写法偏好更能暴露成本。

如果项目需要静态生成、请求时 HTML、文件路由或服务端接口能力，应评估元框架如何组织这些合同。SSG 可以部署到静态服务器；SSR 还需要请求运行时和缓存隔离。使用 SSR 不自动保证首屏更快，服务器等待和客户端激活成本都需要量测。

如果目标是小体积嵌入、微交互、Web Components 或对运行时性能有特殊要求，可以评估轻量框架。它们适合特定问题，但团队招聘、调试资料和组件生态要提前验证。

如果目标是移动 App、小程序、桌面端或多端统一交付，需要进入跨端框架。跨端不是“写一次到处完美运行”，仍要处理平台能力、组件差异、包体积和发布审核。

## 阅读路径

先看 [组件模型比较](../frontend-foundations-series/23-framework-architecture-comparison.md)，确定状态归属和更新机制；再看各框架页选择初始化、组件和数据入口。已有应用先保留当前构建与部署合同，从一个功能切入验证，不把“换工具”当作自动消除业务复杂度的办法。

构建工具页分别用子路径应用、异步报表、金额库和HTML活动页说明不同产物。库开发重点读 [Rollup](./rollup.md) 的消费格式与外部依赖，应用开发重点核对 [Vite](./vite.md)、[Webpack](./webpack.md) 或 [Parcel](./parcel.md) 的HTML与资源交付。整体上线过程见 [前端部署](../deployment/)。

## 排查入口

| 现象 | 优先检查 |
| --- | --- |
| 框架选型争议 | 先明确渲染模式、团队经验、组件生态和部署方式 |
| 首屏慢 | 是否需要 SSR/SSG，包体积和数据请求是否可拆分 |
| 状态混乱 | 本地状态、全局状态和服务端缓存是否边界清晰 |
| 构建复杂 | 是否使用了过多插件，是否能回到 Vite 或框架默认配置 |
| 跨端适配成本高 | 平台 API、组件差异、样式单位和发布流程是否提前验证 |
