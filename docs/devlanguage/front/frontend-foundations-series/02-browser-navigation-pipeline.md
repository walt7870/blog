# 浏览器导航流程：URL、DNS、HTTP、DOM 与渲染管线

打开商品详情页时，浏览器既要拿到资源，也要把资源解释成可交互的界面。“服务器已返回 HTML”和“用户已经看到商品、能够购买”是不同结果。排查慢页面时，要确定时间花在请求之前、响应等待、资源加载还是主线程处理。

![导航、资源发现与浏览器渲染关系](/front/frontend-foundations-series/ep02-flow.svg)

## URL 到响应：不一定每次都重新建连

在 `https://example.com/products?id=42#reviews` 中，协议、主机、路径和查询决定请求目标；片段 `#reviews` 不发送给服务器，通常用于页面内定位。只有片段变化的导航通常也不会重新下载整个文档。

浏览器可能使用 HTTP 缓存、Service Worker 响应或已有连接。需要网络时，再按实际情况解析域名并建立连接；HTTPS 提供传输加密与服务器身份验证。HTTP/1.1、HTTP/2 常基于 TCP，HTTP/3 基于 QUIC，不能把所有访问都描述成固定的“DNS → TCP → TLS”三次全新操作。

响应状态、`Content-Type`、缓存与安全响应头共同影响后续行为。重定向可能引入额外请求；304 让浏览器复用已有响应体，并不返回一份新 HTML。请求失败、下载内容类型错误和脚本执行失败，也属于不同阶段。

## 解析会发现资源，并与下载交错

HTML 可以边下载边解析生成 DOM。解析器和预加载扫描会发现样式表、脚本、图片等资源；这些资源不必等整份 HTML 下载完才请求。CSS 解析形成样式规则，浏览器将它们与 DOM 结合计算样式。DOM 不会先“变成 CSS”，两者是不同输入。

普通经典脚本可能暂停 HTML 解析；带 `defer` 的经典外部脚本在解析后按顺序执行，模块脚本默认具有类似延后解析执行的行为。`async` 脚本下载完成后执行，不能依赖它与其他脚本的先后关系。样式表通常阻塞首次渲染，也可能间接延迟需要等待样式表的脚本，但它不等同于始终阻塞 HTML 解析。

```html
<link rel="stylesheet" href="/product.css">
<script src="/product.js" defer></script>
<main><h1>商品详情</h1><img src="/product.webp" alt="商品正面"></main>
```

这里商品脚本在 DOM 解析完成后运行，不需要靠任意延时等待标题出现。图片下载与样式、脚本下载可以交错，实际调度仍受资源优先级和连接条件影响。

## 从样式到像素：更新不总是走完整流程

样式计算确定元素的最终规则，布局计算尺寸和位置，绘制生成视觉内容，合成将相关图层组织成屏幕结果。修改宽度可能需要重新布局；某些 transform 动画可以只更新合成阶段。是否建立独立合成层、是否重绘，应以 Performance 记录为准，不能仅由属性名断言“完全不占主线程”。

如果列表脚本持续执行长任务，即使数据和图片已下载，浏览器也可能迟迟无法响应点击。相反，白色占位也可能只是主图仍在等待网络。先用 Network 分清资源等待，再用 Performance 分清脚本、布局和绘制成本。

## 三种就绪时间分别回答什么

| 观测点 | 能说明什么 | 不能保证什么 |
| --- | --- | --- |
| `DOMContentLoaded` | 文档解析及需等待的延后脚本执行完成 | 图片完成、异步数据完成、交互流畅 |
| `load` | 文档及会阻塞该事件的相关资源完成 | 所有懒加载资源或后续业务请求完成 |
| 业务就绪标记 | 例如商品数据已展示且购买按钮可操作 | 所有设备与网络都有相同体验 |

用 `performance.getEntriesByType('navigation')[0]` 可查看当前文档导航的响应、DOMContentLoaded 和 load 时间。跨站资源的细粒度时间可能受 Timing-Allow-Origin 等限制，缓存和连接复用也会改变字段；不能把某个值为零简单解释成阶段没有发生。

## 商品页加载慢时的检查顺序

在 DevTools 打开 Network 后重新导航，分别记录正常缓存和禁用缓存的条件。先看文档是否重定向、等待响应是否过长，再看主图、CSS 和脚本何时开始下载。响应已完成后仍卡顿，再录制 Performance，定位长任务与布局。

验收时同时记录“主要内容出现”和“购买流程可完成”，不要只比较 load 数字。性能指标的测量范围见[Web 性能工程](./27-web-performance-engineering.md)。
