# CSS 层叠、选择器与样式计算

购买按钮本应是绿色，却被组件库改成灰色。把新规则挪到文件最后有时有用，有时完全无效，因为浏览器先筛选匹配声明，再按来源、重要性和层叠层等条件比较；选择器权重只是其中一步。

![样式声明从匹配到层叠和计算的路径](/front/frontend-foundations-series/ep07-flow.svg)

## 从同一个属性开始检查

一次只追踪一个属性，例如按钮的 color。先确认选择器命中、媒体条件成立、属性和值有效，然后在 Styles 查候选声明及划线原因，再到 Computed 查看结果。没有命中的选择器不会参加后面的权重竞争。

浏览器样式、用户样式和作者样式是不同来源。普通声明中作者样式优先于用户与浏览器默认样式；important 声明会反转来源优先关系，保护用户和浏览器的重要规则。动画与过渡还有独立的层叠位置，过渡期间的值甚至可优先于 important。调试动态颜色时，不能只比较静态选择器。

## layer 先于选择器权重

```html
<style>
  @layer vendor, app;
  @layer vendor { #buy { color: #666; } }
  @layer app { .buy { color: #17633b; } }
</style>
<button id="buy" class="buy" type="button">立即购买</button>
```

在这两条同为作者普通声明的规则中，后声明的 app 层优先，按钮为绿色，即使 vendor 使用了更强的 id 选择器。没有分层的作者普通声明通常又优先于显式层中的普通声明。important 会反转层顺序，因此不能把“后层总赢”当成通用规则。

内联 style 在同一重要性下也有特殊位置。排查时依次区分来源与重要性、层和内联位置，再比较同等条件下的 specificity；不要用不断叠加 id 或 important 掩盖层次设计问题。

## specificity 是分栏比较

权重按 id、类/属性/伪类、元素/伪元素分栏从左向右比较，不是任意累加的十进制分数。`#buy` 强于任意数量普通类的组合；`:where(...)` 本身及其参数权重为零，`:is()`、`:not()` 和 `:has()` 则采用参数中的最高权重，嵌套选择器还要结合其上下文判断。

在前述层叠条件和权重相同时，有 @scope 的规则还要比较作用域邻近性，最后才是出现顺序。日常组件不使用 @scope 时，这一步无需额外构造，但不能把“权重一样就只看顺序”用于所有 CSS。

## 继承不参与子元素的权重竞赛

父容器即使用很强的选择器设置 color，子元素直接命中的普通 color 仍可替代继承值。继承用于补充没有直接胜出值的继承属性，不能把父选择器权重加到子元素上。color、font-family 常继承，margin 和 border 通常不继承；inherit、initial、unset、revert 和 revert-layer 可显式改变取值路径。

自定义属性也参与层叠与继承。`color: var(--accent, green)` 的回退值只在变量缺失或无效等情况下使用；若变量存在但替换后不符合 color 语法，不能期待它自动退回上一条 color 声明。最终样式异常时要展开变量链。

## 计算值与实际尺寸分开看

百分比、字体相对单位和布局约束不一定在同一阶段完全变成像素。规范区分指定值、计算值、使用值等阶段；`getComputedStyle()` 返回解析值，对某些属性接近使用值，不能说它永远直接返回规范的计算值。

在 DevTools 中先找到胜出声明，再检查变量、继承和尺寸依赖。用 `getBoundingClientRect()` 看最终几何范围时，还要注意 transform 会影响测得矩形，而不等于元素的原始布局宽度。

## 验证按钮覆盖问题

运行示例，确认绿色来自 app 层；反转层声明顺序，观察灰色胜出。再在层外增加 `.buy { color: red; }`，普通声明会变红。最后删除临时规则并验证 hover、focus、disabled 与深色主题，避免仅修复默认状态。更详细的空间计算见[布局系统](./08-css-layout-flex-grid.md)。
