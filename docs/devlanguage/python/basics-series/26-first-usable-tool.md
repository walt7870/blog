# 学完 Python 基础后，怎样从空目录做出第一个可用工具

> 对应视频：EP26《学完 Python 基础后，怎样从空目录做出第一个可用工具》

Python 基础的终点不是背出术语，而是在遇到一张真实表时，知道怎样让输入、规则、结果和错误都可解释。

## 把概念放回一条完整动作

![从最小样例到实际交付的验证闭环](/python/python-tool-delivery-loop.svg)

这些能力不是互相替代，而是位于同一个工具的不同层。运行环境不清楚，再好的规则也无法启动；数据表示错误，循环只会批量放大错误；没有日志和 README，结果就只能由作者解释。

## 第一个项目：客户名单检查器

1. 创建项目目录、虚拟环境和 `run.py`。
2. 放入两三条脱敏的 `customers.csv` 样例。
3. 用 `csv.DictReader` 读入每一行。
4. 写一条规则，例如手机号或城市不能为空。
5. 把待补记录写入独立的 `outputs/` 目录。
6. 记录输入数量、成功数量和失败原因。
7. 写 README，说明运行命令、输入格式和输出位置。

最小项目不需要爬虫、Web 服务或大模型。先让一条完整的数据处理链可靠地跑通，再逐步加入渠道清洗、城市统计、命令行参数或接口同步。

## 用固定样例收束项目

先复用 [参数版工具](./23-argparse-config)作为 `run.py`，保持第一版只检查手机号，不把尚未实现的城市规则写进说明。将 [CSV 三行样例](./11-csv-read-write)放入 `customers.csv`，执行：

```bash
python3 run.py --input customers.csv --output outputs/missing.csv
```

输出应有表头 `name` 和一行韩梅梅。然后把李雷的手机号改为空，第二次写入另一个结果文件，应多出李雷；恢复输入后结果也应恢复。这组前后对照说明规则确实作用于输入，而不是硬编码一份输出。

| 验收输入 | 预期行为 | 核对重点 |
| --- | --- | --- |
| 三行正常样例 | 一行待补 | 原始客户数量与筛选口径 |
| 只有合法表头 | 只有结果表头 | 空表不是缺列 |
| 缺少 `phone` 列 | 失败且不生成结果 | 错误指出输入合同 |
| 输出指向原输入 | 拒绝运行 | 原件内容不变 |
| 输出已存在 | 默认拒绝覆盖 | 重跑不会悄悄替换旧结果 |

城市检查、异常原因列、分组和日志可以按此闭环逐项加入。每加一项就补对应样例、预期结果和说明，之后再用 [交付检查器](./24-delivery-package)检查目录，并在新虚拟环境重跑同一套样例。

## 项目完成的标准

- 正常样例和边界样例都得到预期结果。
- 每个输出都能回到输入来源。
- 坏数据有明确记录，而不是静默丢失。
- 别人按 README 能在新环境中运行。
