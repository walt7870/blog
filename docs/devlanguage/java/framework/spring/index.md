# Spring / Spring Boot

Spring 不是一组注解的集合，而是一套应用运行模型：启动阶段发现组件、建立对象图并挂接扩展能力；请求阶段复用对象图，通过 Web、事务和数据访问基础设施完成一次业务调用；Spring Boot 则在这套模型之上提供配置、自动装配、内嵌服务器、诊断和交付能力。

本专题使用订单系统串联对象装配、方法代理、HTTP 请求和应用就绪。源码阅读以 Framework 7.0 与 Boot 4.1 为主，订单练习固定 Boot 3.5.15 与 Java 17；两条版本线的依赖和测试入口分别说明。

![Spring 各机制的阅读关系](/spring/spring-learning-map.svg)

例如“创建一笔 199 元订单”：IoC 把仓库和时钟交给服务，MVC 把 JSON 变成业务命令；需要数据库事务时，AOP 在服务调用边界接入事务管理器。Boot 准备这些机制所需的配置与默认组件，但订单能否创建仍由业务规则判断。

## 按问题进入机制

| 实际问题 | 机制与阅读入口 | 可以做的验证 |
| --- | --- | --- |
| Service 缺少仓库，或出现两个实现 | [IoC 容器](./ioc.md)：定义来源、候选选择、作用域和销毁 | 删除一个仓库定义，观察启动失败；为多实现增加限定符 |
| 同类内部调用后，事务规则没有应用 | [AOP 与事务](./aop.md)：代理创建、调用边界与回滚 | 比较代理外部调用和 `this` 自调用，检查事务与数据库结果 |
| 接口返回 404、400、405 或 415 | [Spring MVC](./mvc.md)：映射、参数转换、校验和响应 | 分别改变路径、方法、JSON 和 Content-Type，定位拒绝阶段 |
| 注解存在但行为没有出现 | [注解运行机制](./annotations.md)：读取者、处理阶段和基础设施 | 检查定义、代理与映射表，确认调用经过的对象 |
| 不清楚接口背后的完整过程 | [运行生命线](./runtime-model.md)：连接启动链与请求链 | 从 `main()` 追踪到订单 JSON，区分创建对象和使用对象 |

## Boot 从启动到生产

Boot 的学习顺序可以沿“输入 → 定义 → 实例 → 就绪 → 运行”推进。修改端口属于配置输入；定义数据源后默认连接池退让属于条件与定义；端口监听却尚未执行完 Runner，则属于启动和就绪的边界。

## 如何阅读

第一次接触 Spring，可从“解决了什么问题”进入，下载其中的订单练习，再阅读运行生命线与 IoC。已经能够开发接口但经常遇到事务、注入或 404 问题，可以按上表直接进入机制。准备升级或排查生产启动问题时，同时关注版本差异、失败实验和证据链，不直接把内部源码细节当作稳定 API。

Security、Spring Data、Integration、Cloud 等独立生态项目只在本专题中说明接入点；它们的内部原理在独立专题展开。
