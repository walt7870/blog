# Rust

Rust适合需要控制资源、处理不可信输入或长期运行的工具和服务。所有权、借用与类型约束能把许多内存误用和数据竞争提前到编译阶段；死锁、业务竞态、输入规则和资源耗尽仍需设计与验证。

例如一个日志过滤工具，读取文件时拥有文本，搜索函数只借用文本，输出后释放资源；如果改成并发服务，还要决定谁持有连接、队列多长、取消时如何退出。Rust的学习可以沿这条资源链推进。

## 所有权先从一个可运行例子开始

```rust
fn main() {
    let name = String::from("Rust");
    print_language(&name);
    println!("仍由main持有：{name}");
}

fn print_language(value: &str) {
    println!("读取：{value}");
}
```

`name`拥有字符串，函数接收`&str`，只读期间不取得字符串所有权，调用后`main`还能使用它。若把参数改为`String`并直接传入`name`，调用方之后再使用它通常会得到移动后使用的编译错误。

所有权不依赖“在栈还是堆”判断：是否隐式复制看类型有没有实现`Copy`。`Rc/Arc`等抽象可以共享底层资源，每个句柄仍有自己的归属；克隆`Arc`增加引用计数，不会深拷贝整份内容。

## 选型边界

| 约束 | Rust可能提供的帮助 | 仍需验证 |
| --- | --- | --- |
| 解析外部文件与协议 | 安全切片、枚举与显式错误 | 大小限制、算法复杂度和格式正确性 |
| 低延迟服务 | 无通用GC、明确分配与同步 | I/O、锁、调度、尾延迟及内存峰值 |
| CLI与边缘组件 | 原生二进制、启动与资源控制 | 目标系统库、架构和更新方式 |
| 旧系统热点替换 | FFI或语言绑定逐步引入 | ABI、对象寿命、异常和线程合同 |

如果主要约束是交付速度、框架集成或团队经验，应先用真实小模块比较成本。编译期安全不能代替对业务目标、生态支持和团队维护能力的判断。Rust 2024 Edition从1.85.0起可用；项目还需单独固定编译器版本和最低支持版本，不能把Edition年份当作编译器版本。
