# Rust 学习路线与选型

按能独立完成的任务安排学习：先把输入转换成结果，再明确资源归属，然后把规则收进类型，最后加入并发与交付约束。无需先把异步、宏、unsafe和所有生态库同时学完。

![Rust按可交付能力推进的学习路线](/rust/learning-delivery-route.svg)

## 从同一个订单工具逐步推进

| 阶段 | 实际任务 | 达成标志与入口 |
| --- | --- | --- |
| 语法与控制流 | 数量文本转为金额 | 能解释非法数量和溢出，见[基础概念](./basic.md) |
| 所有权与借用 | 读、修改、移交导出内容 | 能复现并修正移动后使用，见[所有权](./ownership.md) |
| 类型与错误 | 限制数量、区分失败原因 | 库外无法绕过私有构造，见[类型系统](./type-system.md) |
| 工程交付 | 发布可运行CLI | 测试stdout/stderr和退出码，见[动手实践](./hands-on.md) |
| 服务与任务 | 加HTTP适配和有界队列 | 区分输入失败、排队和执行结果，见[实战](./project-practice.md) |
| 目标平台 | 在实际机器部署 | 运行库、配置、关闭与恢复验证，见[工具链](./tooling.md) |

例如“会借用”不是记住 `&` 的语法，而是能说清解析函数为何只借用、队列为何需要接管、何时需要独立副本，并在调整后保持测试通过。遇到错误回到最小例子验证，不靠把所有值都放进 `Arc<Mutex<_>>` 绕过设计。

## 根据运行环境分支

后端方向从Tokio的调度、超时、背压和关闭开始，再引入数据库池与事务。性能瓶颈在外部数据库时，先改查询和容量，并不一定需要重写语言。

系统方向重点补布局、原生库、FFI与目标平台。接管旧C接口时先规定缓冲区长度、编码、释放函数、线程和错误边界，不能把“Rust内部安全”扩展为整个跨语言系统安全。

浏览器WASM方向先测JS与WASM的数据传输成本，再决定是否迁移图像、压缩等计算热点。MCU方向从标准Rust基础进入 `no_std`、PAC/HAL、中断与板级调试；没有硬件时只能验证有限的编译或模拟行为，不声称时序已通过。

## 结合原有经验调整

Java/Go开发者应重点练习资源归属，避免默认共享所有对象；C/C++开发者应区分安全抽象与unsafe责任，不把指针习惯直接搬入借用接口。Python或JS开发者可先做CLI，逐步补静态类型、编译和系统资源，不必从多线程服务器起步。

克隆可以合理，生命周期常能推断，Trait也不必过早建立层次。是否引入高级机制，应由数据共享、性能或扩展需求驱动，而不是学习清单上出现了某个名词。

## 采用前做小试点

先选择接口稳定、可单独回归的CLI、解析器或热点模块，固定输入、平台和比较口径，记录正确性、内存、延迟与维护成本。保留原实现和回退路径，再判断是否扩大。

业务规则快速变化、依赖特定成熟框架、团队缺少维护经验且交付期紧时，Rust未必有净收益。选型结论应落在具体约束上，详见[优势与代价](./advantages.md)和[生态边界](./ecosystem.md)。章节索引保留在[系列目录](./video-series.md)，它不代表所有配套视频已发布。
