# AI 编程实战手记

过去两个月，我手上同时推进着十几个项目：云平台的五个服务、私有化语音识别交付、移动端 SDK、会议纪要应用、全双工语音服务，还有公司的 GitLab、CI 和模型接入网关。代码的大部分改动、测试脚本、部署手册和验收报告，都是在 Claude Code 和 Codex 这两类 Coding Agent 的协作下完成的。8 月只开了 2 个 Codex 会话，9 月 13 个，10 月 49 个，Claude Code 那边另有几十个项目会话。

这组文章记录的是这段时间里真实发生的事情：Agent 怎样干活，多个会话怎样分工交接，规则写在哪里，结果凭什么算数，出过哪些错，以及哪些活我会交出去、哪些不会。读完以后，你应该能判断一项任务适不适合交给 Agent，知道交出去之前要准备什么，也知道它交回来的东西该怎么检查。

文章面向两类读者。一类是听说过 AI 编程、还没在真实项目里用过的开发者和技术管理者，可以把它当作入门科普；另一类已经在用，想看看别人怎样把它放进日常交付流程。概念和方法的系统讲解在 [AI 编程深度系列](../coding-agent-series/)，这里不重复，只讲实际怎么做、为什么这样做。

## 六篇文章

第一篇从最基础的问题讲起：同样叫“AI 写代码”，补全、对话和 Agent 到底差在哪里。关键在于 Agent 会自己运行命令、读取结果、再决定下一步，这个循环既是它能力的来源，也是风险的来源。

第二篇讲多个会话怎样分工。一个人同时开好几个 Agent 会话时，最先遇到的问题不是模型够不够聪明，而是会话结束以后事实去了哪里：下一个会话怎样接手，两个会话怎样避免改到同一份文件。

第三篇讲规则。项目红线写进仓库的 `AGENTS.md`，可复用的做法封装成技能，生产操作要一次一授权。这一篇会列出我在项目里实际使用的规则，以及它们分别防住了什么。

第四篇讲验证。Agent 最常见的问题是“说完成了，其实没完成”。解决办法不是更严厉的提示词，而是让每份证据写清它证明到哪一级：编译、单元测试、模拟集成、真实调用，还是线上回读。

第五篇是几次出错的复盘：一次验收脚本误判引发的约 13 分钟中断，几次没有证据支持的“已完成”，以及 CI 里 AI 代码审查门禁从严格启用到停用的经过。

第六篇回到选择：用“结果能否验证”和“操作能否撤回”两个问题，划分哪些任务交给 Agent 做完，哪些由它准备、人来批准，哪些仍由人主导。

## 文中案例的边界

案例来自真实项目，客户、人员、服务器地址和内部域名都已去掉，保留技术因果。文中的数字带着各自的范围：测试数量是某一轮的结果，耗时是单次记录，不外推为普遍效果。工具版本和产品功能变化很快，涉及具体工具时以 2026 年 10 月的使用情况为准。

如果只想读一篇，建议从第四篇开始：验证方式决定了 Agent 交回来的东西能不能用，这一点在任何工具、任何模型上都成立。
