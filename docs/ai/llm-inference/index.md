# 大模型推理优化

把一个训练好的大模型搬上线、让很多人同时使用，和把它训练出来是两件目标不同的事。训练要把海量数据喂进去，让模型学会；推理要在延迟和成本的约束下，尽可能快、尽可能多地生成回答。同一个模型，换一种部署方式，速度可以差好几倍，一张显卡能服务的人数也可以差一个数量级。

这个系列从“模型怎样一个字一个字地写出回答”讲起，一直讲到推理引擎的源码、量化、投机解码、多卡与 P/D 分离部署，以及压测和生产运维。读完以后，你应该能看着一个推理服务回答三个问题：时间花在哪里，显存花在哪里，某项优化在改善哪一段、又付出了什么代价。

## 先读哪里

不需要会写 CUDA，也不需要先学 Transformer。前五篇只要求你用过聊天助手，知道“模型”“显卡”大概是什么；公式出现时都会给出一组可以手算的数字。第 6 篇开始需要一点硬件常识，文中会从 GPU 的基本结构讲起。

![系列的五个部分：从一次推理怎样发生，到瓶颈原理、引擎技术、压缩加速和规模化工程](/ai/llm-inference/series-map.svg)

全系列用同一个例子贯穿：公司内部的**资料助手**。员工小林问它“年假怎么申请？”，它读取制度、生成回答。一开始只有小林一个人用，后来上传了整本员工手册，再后来全公司同时在用，还要求能用语音提问。每一次规模变化，都会引出一类新的推理问题。

为了让数字可以手算，模型统一用 **Llama-3.1-8B**（约 80 亿参数，32 层，8 个 KV 头），硬件统一用一张 **80 GB 显存的 NVIDIA H100 SXM**。换成别的模型和显卡，公式不变，代入各自的配置即可。

## 两种读法

第一次接触推理，按顺序读第 1—7 篇，再挑第三部分中你关心的机制。这七篇读完，你已经能解释“为什么首字慢”“为什么人一多就卡”“为什么显存总是不够”。

已经部署过模型、想解决具体问题，可以按现象直接跳：首字慢看第 5、10、11 篇；人多就慢看第 9、16 篇；显存不够看第 4、8、14 篇；想证明某项优化有效看第 20 篇。

FP16、BF16、FP8 这些数值格式本身的原理，在独立的[模型数值精度](../precision/)专题里从零讲起，第 14 篇只讲它们用在推理里的取舍。

接下来从[第 1 篇：推理系统的分工](./01-inference-system.md)开始，看看你在聊天窗口按下发送以后，应用、推理引擎、模型和 GPU 分别接手哪一部分工作。
