# 大模型架构

问聊天助手一句“年假怎么申请？”，它一个字一个字地写出回答。每写一个字，模型都要把整段对话切成 token，把每个 token 变成几千维的向量，让这些向量穿过几十层同样结构的计算，最后对词表里十几万个候选逐一打分，挑出下一个字。这套结构叫 **Transformer**，2017 年为机器翻译提出，今天几乎所有大语言模型都建立在它之上。几十层里每一层都只有两个主要部件：让每个位置去看上下文的**注意力**，和对每个位置单独做变换的**前馈网络（FFN）**。主流大模型的大部分参数都在 FFN 里，以 Llama-3.1-8B 为例占 70%；KV Cache 和长上下文成本则主要由注意力决定。

这个系列讲清主流大语言模型的内部结构和工作原理：每个部件做什么、输入输出是什么形状、参数和计算花在哪里；GQA、MLA、MoE、RoPE 外推、滑动窗口、线性注意力这些改动分别为了解决什么问题、付出了什么代价；Llama、Qwen、DeepSeek、Mistral、Gemma、GLM、Kimi、gpt-oss 这些模型具体选了哪些设计。读完以后，你应该能看懂任意一个开源模型的 `config.json` 和 Transformers 里的模型源码，手算它的参数量、每个 token 的计算量和 KV Cache 大小，并在新模型发布时判断它在架构上改了什么、为什么改。

## 先读哪里

不需要会推导反向传播，也不需要先读完深度学习教材。知道“模型是一堆参数，训练是在调这些参数”就够了；没有这个印象，可以先看站内的[模型训练入门](../foundations/)。矩阵乘法会反复出现，每次都会写明形状，并给一组能手算的小数字。

![大模型架构系列分四个部分：一个 token 的旅程，架构演进，主流模型拆解，多模态与读懂模型](/ai/llm-architecture/arch-series-map.svg)

全系列沿用站内另外三个系列里的公司内部**资料助手**：员工小林问“年假怎么申请？”。这里跟着这句话进入模型内部，看它被切成哪些 token，“申请”怎样通过注意力看到“年假”，FFN 怎样往向量里加入相关的知识，输出层怎样给出回答第一个字的概率。后面讲 MoE、长上下文和多模态时，继续用资料助手的需求举例：把整本员工手册放进上下文，上传报销单截图提问，用语音提问。

计算类例子统一用 **Llama-3.1-8B**（约 80 亿参数、32 层、隐藏维度 4096），和[模型训练与调优](../model-training/)、[大模型推理优化](../llm-inference/)两个系列的数字可以直接对照；动手实践用能在笔记本上跑的 **Qwen2.5-0.5B-Instruct**。各模型的配置以 2026 年 10 月下旬 Hugging Face 上的官方 `config.json`、官方技术报告和 Transformers 源码为准。

## 两种读法

第一次系统了解大模型内部，先读第 00 篇建立 Transformer 的整体印象，接着按顺序读第 1—8 篇，再跟着[实践篇](./layer-practice.md)在自己电脑上拆一次小模型。这十篇读完，你已经能对着任何一个开源模型的结构图说清每一块在做什么。之后读第 9—12 篇理解演进，第 13—16 篇挑感兴趣的模型家族读。

带着具体问题来的，可以直接跳：想知道 Transformer 整体长什么样，看第 0 篇；想知道 FFN 是什么，看第 5 篇；Q、K、V 没搞懂，看第 3 篇；KV Cache 为什么这么大、GQA 和 MLA 怎样省，看第 4 篇；MoE 的“总参数”和“激活参数”，看第 10 篇；上下文长度能不能再长，看第 7、11、12 篇；拿到一个新模型想快速读懂，看第 18 篇和第 19 篇的对比表。

模型是怎样训练出来的，是[模型训练与调优](../model-training/)系列的内容；训练好的模型怎样高效部署，是[大模型推理优化](../llm-inference/)和[推理引擎与框架](../inference-engines/)两个系列的内容。本系列讲到 KV Cache、量化、投机解码时只讲架构本身的影响，并链接到那里。
