# 语音识别与语音合成

语音技术处理随时间变化的声学信号。完整语音交互通常不只有一个模型，而是语音活动检测、降噪、识别、语言理解、回答生成和语音合成的组合。

## 三类核心能力

| 能力 | 输入 | 输出 |
| --- | --- | --- |
| ASR 语音识别 | 音频 | 文本；时间戳能力取决于模型与接口 |
| TTS 语音合成 | 文本和声音条件 | 音频 |
| 说话人技术 | 音频 | 身份、分段或声纹表示 |

## 语音识别链路

![语音采集、VAD、识别、结果稳定与合成的链路](/ai/speech-runtime-contract.svg)

- VAD 判断哪里有人声，减少无效计算。
- 声学模型把音频映射到文字单位或表示。
- 解码器结合模型分数和语言约束形成文本。
- 热词可能作为解码偏置、上下文提示或后处理词典；是否支持、何时生效需要看接口合同，不能一律画在标点之后。

降噪、回声消除、特征提取与 VAD 的位置因实现而异；全双工助手常需要先消除扬声器回声，避免把自己的播报当成用户语音。部分端到端识别器内部完成特征提取，不应再重复处理。

流式识别边接收边输出，中间文本可能被修订；离线识别能利用更完整上下文，但效果还取决于模型、音频和解码配置，应在同一测试集比较。VAD 判定静音不等于用户语义完整，也不等于 ASR 的最终结果已经到达，应用要分别处理断句、结束输入与结果确认。

## 语音合成链路

传统 TTS 通常分成文本规范化、声学模型和声码器三段。这是一种常见分解，不是所有模型的显式模块：CosyVoice 这类新模型先用语言模型生成语音 token，再解码成波形。应用仍需核对文本读法、声音条件、输出采样率和分块顺序。

“2026-07-10”“¥19.9”和英文缩写如何读，属于文本规范化问题；停顿、重音和情绪属于韵律问题；声音是否自然、是否有噪声，与声学模型和声码器都有关。

## 评估

- ASR：WER、CER、关键词召回率、实时因子、首字延迟。
- TTS：自然度、可懂度、说话人相似度、韵律、生成速度。
- 语音交互：端到端任务成功率和用户打断响应。

总体字符错误率可能掩盖专有名词问题，应单独评估数字、地址、人名、产品名和业务关键词。

## 常见工程问题

- 远场、噪声、混响和多人重叠说话。
- 方言、口音和中英文混说。
- 音频采样率、声道和编码不一致。
- 流式分段切断完整语义。
- 合成声音机械，停顿和重音不自然。
- 声音克隆涉及授权、冒用和隐私风险。

## 实时语音助手

端到端体验取决于整条链路，而不只是模型准确率：

1. 快速判断用户开始和结束说话。
2. 流式转写并保留可修正空间。
3. 根据上下文理解意图。
4. 生成简洁、适合口语的回答。
5. 流式合成并支持用户打断。
6. 对业务动作核对身份与已有授权，根据政策触发确认，并由业务服务保证幂等。

语音系统的质量来自正确率、延迟和交互节奏三者共同平衡。

例如“取消订单 A102”，中间结果可能先是“A10”，不能立即执行取消。界面可以展示可修订文本，业务动作则等待稳定的意图和必要参数，再调用受控接口。用户打断播报时，需要同时停止旧播放、清理未播音频并阻止旧回答的迟到块重新入队，不能只暂停播放器。
