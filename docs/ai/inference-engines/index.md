# 推理引擎与框架

[大模型推理优化](../llm-inference/)系列按机制讲了 PagedAttention、连续批处理、前缀缓存、量化、投机解码、分布式和 P/D 分离。真正部署资料助手时，这些机制都封装在某个框架里：在 GPU 服务器上多半是 vLLM 或 SGLang，追求 NVIDIA 硬件极致性能时是 TensorRT-LLM，在笔记本上是 llama.cpp、Ollama 或 MLX-LM，规模大了还会在引擎之上加一层 Dynamo 或 llm-d。同一个机制在不同框架里的实现、默认值和开关位置都不一样，一个参数的含义在两个框架之间可能完全不同。

这个系列按框架组织，每个主流框架单独一篇，尽量完整地讲清它为什么出现、内部由哪些进程和模块组成、一个请求怎样流过、支持哪些模型和硬件、关键参数怎样调、怎样部署到生产、有哪些已知的坑，最后一篇把它们放在一起对比并给出选型路径。读完以后，你应该能看懂任意一个框架的启动日志和参数表，知道它的默认值在哪些地方和别人不同，并为自己的场景列出该实测的候选。

## 先读哪里

建议先读过推理系列的第 1—7 篇，知道 Prefill 和 Decode、KV Cache、显存账本和 TTFT/TPOT 是什么；本系列遇到机制时直接链接推理系列对应的篇，不再重讲。只想快速上手跑起一个服务，推理系列的[实践：用 vLLM 跑起资料助手](../llm-inference/vllm-quickstart.md)更合适。

![推理框架分三类：编排与 KV 缓存层管理多个引擎实例；数据中心引擎面向 GPU 服务器上的多人并发；本地与端侧框架面向个人设备](/ai/inference-engines/engines-landscape.svg)

全系列沿用公司内部的**资料助手**，服务端例子用 Qwen3-8B 或 Llama-3.1-8B 跑在一张 80 GB 的 H100 上，本地例子用 Apple 芯片的笔记本。版本以 2026 年 10 月下旬的正式发布为准，每篇都核对了对应版本的源码。数据中心框架的命令按源码和文档核对，没有在 GPU 上实际运行；llama.cpp、Ollama 和 MLX-LM 的命令在 Apple M4 笔记本上实际跑过，篇中分别注明。

## 两种读法

要为团队选框架，先读[第 09 篇](./09-comparison.md)的对比和选型路径，圈出两三个候选，再回到对应的单篇看细节，最后用推理系列[性能测试与分析](../llm-inference/20-benchmark.md)里的方法拿自己的请求实测。

已经在用某个框架、遇到具体问题，直接读那一篇：每篇都有关键参数表、常见问题表和“版本与变化”一节，升级前先看后者。
