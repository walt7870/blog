# 模型推理系列

在聊天窗口输入一句话，模型为什么要等一下才开始回答？同一个模型，为什么换台机器就快慢不同？FP16、BF16 又和这些有什么关系？这个系列从一次普通问答开始，逐步解释答案怎样生成、机器怎样承担计算，以及人们怎样让它跑得更省、更快。

## 模型怎样把输入变成结果

小林打开公司的资料助手，问：**“年假怎么申请？”** 回答开始时有一点等待，之后一块块出现。过几天，他上传整份手册，同事也一起使用，服务开始变慢。再后来，他希望直接开口提问，并听到语音回答。

模型接收输入、利用已经学到的参数计算结果，这个过程叫作**推理**。聊天助手生成文字、语音识别把录音变成文本、语音合成把文字变成声音，都在做推理。

模型能回答问题之后，还会遇到一串很实际的麻烦：答案来得慢、显存装不下、多人使用时排长队。推理系统要把模型、设备和请求组织起来，在回答质量、等待时间和运行成本之间作出安排。vLLM、SGLang 等推理引擎就承担了其中的许多工作。

## 从一个人的问答开始

起初只有一句提问，后来添了附件、追问和一群同事。助手的工作量一路上涨，藏在背后的技术问题也跟着冒出来：先是等答案，再是挤显存，最后连排队都成了一门学问。

先抓住一个问题就够了：你点下发送后，机器做了哪些事？前两篇会跟着这句话走一遍，再解释为什么生成过程需要时间和空间。

## 从哪里开始读

第一次接触这些概念，可以先读前五篇。第 1 篇认识模型、参数和推理；第 2 篇看答案怎样逐段产生；第 3 篇看机器要存什么；第 4、5 篇再解释如何省去重复工作，以及多人同时使用时如何排班。这段阅读只需要有使用聊天助手的经验，暂时用不到 Python、GPU 或安装命令。

如果主要想了解 **FP32、FP16、BF16**，读完第 3 篇就可以跳到[第 14 篇：数值格式](./14-precision-formats.md)。先理解一个数怎样保存，再读混合精度与量化，比一开始就记各种缩写容易。

第 6—13 篇适合带着实际问题选读：想省资源，看计算优化；准备部署服务，再看引擎、选型与压测。完整路线放在下面，随时可以回来查。

从一个人的短问题，到多人同时使用的语音服务，推理系统始终要处理三件事：怎样完成计算、怎样利用有限的资源，以及怎样把结果及时交给用户。缓存、调度、量化和多卡部署，都会在这条线上找到各自的位置。

接下来从[第一篇：推理系统的分工](./01-landscape.md)开始，看看你按下发送之后，应用、推理引擎、模型和硬件分别接手哪一部分工作。

如果你更关心语音，可以从[语音与多模态推理](./11-speech.md)里的 sherpa-onnx 流程回放和热词实验开始，再进入 [sherpa-onnx 专题](../../basic/acoustics/sherpa-onnx/)学习模型与 API；语音服务中的断句、收尾和角色识别则在[流式语音技术实践](../speech-engineering/)展开。
