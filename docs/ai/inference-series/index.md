# 模型推理系列

小林打开公司的资料助手，问：**“年假怎么申请？”** 回答开始时有一点等待，之后一块块出现。过几天，他上传整份手册，同事也一起使用，服务开始变慢。再后来，他希望直接开口提问，并听到语音回答。

这条逐渐变复杂的使用过程，就是本系列的主线。先从屏幕上的现象开始，再打开请求、显存、缓存和调度，随后进入 vLLM、SGLang，最后回到多卡、语音、选型和实测。

## 由表到里的四个阶段

第一遍按顺序阅读。每篇先用图和例子建立直觉，之后进入机制；公式、支持边界与完整参数放在展开区。每篇末尾回顾已经建立的认识，并给出下一篇自然产生的问题。

<InferenceJourney />

前五篇先不急着比较“谁更快”，而是回答：为什么要等、为什么显存不够、为什么缓存能省工作、为什么很多请求能一起算。建立这些直觉后，框架名称才会对应到具体机制。

## 同一个问题，逐层放大

| 深入一层 | 资料助手出现的现象 | 接着研究什么 |
| --- | --- | --- |
| 屏幕 | 回答停一会儿才开始，一块块出现 | 应用、引擎、prefill 与 decode |
| 机器 | 文档更长、人数更多时装不下 | 权重、KV 与临时空间 |
| 状态 | 同一份制度为什么重复计算 | KV、前缀复用、分页与 attention |
| 调度 | 短问题为什么被长问题挡住 | 连续 batch、分块与队列 |
| 实现 | 相同工作能否更高效 | 量化、编译、推测、vLLM、SGLang |
| 工程 | 多卡与语音该如何部署 | 通信、音频链路、选型与测量 |

类比用于解释关系，不替代技术定义。计算便笺不等于文本笔记，显存工作台不等于实际文件柜，模型也不保证像熟练员工一样理解和核对事实。每篇会在进入机制时说明边界。

## 先观察，再预测，再验证

交互实验在浏览器本地运行，不下载模型。先预测改变人数、长度、缓存或输出方式会发生什么，再操作观察，最后把结果对应回机制。教学模拟、预算估算与真实 GPU 测量会分别标明。

版本快照截至 **2026-10-20**。原理的学习顺序不依赖某一次 release；实际启动与升级仍应对齐安装版本和模型支持。

简要概览见[大模型推理与部署](../llm/inference.md)；语音工程细节见[流式语音技术实践](../speech-engineering/)。现在从[第一篇：推理系统的分工](./01-landscape.md)开始。
