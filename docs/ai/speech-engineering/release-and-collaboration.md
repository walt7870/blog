# 可复现交付与协作

多人维护同一个语音服务时，代码、运行实例、静态页面和交付包可能分别处于不同版本。一个同事修改了源码，另一个同事切换了测试路由，第三个同事更新了页面；此时“最新版本”没有足够明确的含义。实践应围绕候选身份、运行事实和工件记录协作。

## 四种版本分别核对

| 对象 | 核对方式 | 常见误判 |
| --- | --- | --- |
| 源码 | commit 与实际源码树摘要 | 未提交覆盖层被当成纯提交构建 |
| 运行实例 | 路由、监听进程、可执行文件、配置和模型摘要 | PID 文件或目录名被当成正在运行版本 |
| 静态页面 | 反向代理路由、静态目录、资源摘要 | 编译后端就认为页面同步更新 |
| 交付包 | 包内 manifest、镜像与附件摘要 | 文件名的新日期被当成已验收版本 |

尤其要检查静态覆盖路由：页面可能由代理单独读取文件，而不是来自新二进制的内嵌资源。接手者应先画出实际请求路由，再定位运行实例。历史报告记录的是某次观察，不是实时状态。

## 共享资源的切换纪律

为每个实验约定负责人、资源、候选摘要、测试窗口和退出条件。共享加速卡上的旧实例仍占用显存时，盲目新增候选可能把初始化失败伪装成模型不兼容；终止其他人的训练则会破坏现场。

```text
读取当前路由和运行摘要
  -> 确认资源与测试窗口
  -> 准备隔离候选
  -> 候选 ready 与真实 smoke
  -> 比较当前路由仍是预期旧值
  -> 切到候选并回读
  -> 完成验证或回滚
```

比较并交换的要点是：只有当前上游仍等于自己开始时观察到的值，才执行切换或恢复。否则说明另一个维护者已改动路由，应重新协调；无条件“恢复旧端口”可能覆盖他人新版本。

资源不足以让两个实例并存时，采用经过约定的等量停启，保存可启动的回滚工件和配置。不要把候选启动成功等同于流量已切换，也不要用候选的结果描述另一个运行实例。

## 发布编排要能恢复

大模型镜像构建、扫描、压缩、摘要和上传可能耗时较长。应由同一份 release manifest 记录各阶段输入指纹和输出，让中断后可以复用完成的步骤。

```json
{
  "release_id": "example-release",
  "source_tree": "<源码摘要>",
  "model_set": "<模型集合摘要>",
  "runtime_config": "<配置摘要>",
  "stages": {
    "build": {"status": "passed", "artifact": "<镜像摘要>"},
    "acceptance": {"status": "passed", "report": "<报告摘要>"},
    "upload": {"status": "pending"}
  }
}
```

只有输入指纹未变且产物重新核验通过，才复用阶段。模型、依赖或源码变化后必须使相关下游阶段失效；不能拿旧验收报告绑定新镜像。部分下载、截断压缩包和仅存在的对象都不算完成，应完整读取或按适当的完整性规则验证。

大工件采用分离交付时，小附件内记录外部工件摘要和校验方式。短期下载链接只负责访问，长期身份由摘要和受控对象记录承担。使用签名 GET 链接时按同一 HTTP 方法验证，不能以另一个方法的签名失败判定对象不存在。

## 文档修订不必重建模型镜像

先按实际变更选择验证路径。只改手册时，确认镜像与模型摘要未变，再修订附件、包内清单和压缩包摘要；只改通知文案时，更新通知引用。代码变化也不一定能复用所有构建缓存：模型输入合同、原生依赖和运行配置变化，必须进入对应兼容验证。

包内中文文件名要验证 ZIP UTF-8 标志，操作命令要从解压后的包实际运行。外部镜像模式的校验脚本需要明确传入镜像路径，不能假定无参数就能自动找到文件。全新部署、首次启动、重启、只读文件系统和非默认设备映射是不同验证场景。

## 接手记录维护当前状态与历史证据

入口文档写当前链路、证据位置、运行核对步骤和责任人；详细实验留在按主题归档的报告中。每次交接先更新当前状态，再补历史索引。失败实验保留输入、策略和退化原因，已经释放的资源与已停止实例也写清楚，避免后来误恢复。

对外通知只陈述此次工件实际支持的变化。内部报告则保留通过、失败和未验证项；这两种文档职责不同，但对外表述不能超出证据。

## 将一次问题变成长期实践

每个关闭的问题至少留下一个回归用例和一条决策记录：触发条件、根因证据、采用方案、未采用方案、适用边界、验证方法。若经验依赖某个旧后端，则保留历史标签，迁移到新链路前重新验证输入合同和时序。

公开文章保留因果关系、故障模式和判断标准；受控记录保存原始音频、部署标识和精确结果。脱敏时去掉可识别项目的信息，不能把“为什么成功、为什么失败”一起删掉。
