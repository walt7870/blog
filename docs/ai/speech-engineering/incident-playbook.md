# 故障复盘与排查闭环

会议转写出现漏字、串人或断连时，先保留失败现场，再逐层建立证据。原始音频、实际模型输入、协议事件和页面渲染是四个不同对象；它们分别回答“采到了什么”“模型看到了什么”“服务返回了什么”和“用户看到了什么”。

## 漏字：从输入完整性查到模型输出

一类实际故障表现为长句中间缺少一段文字。最初很容易怀疑 VAD 切掉音频，但比对后缺失内容对应的样本仍在模型输入中。此时继续改传输或 VAD，无法解释问题；应该固定输入，进入识别上下文、切分策略和模型输出对照。

先把链路拆成采集 PCM、服务接收 PCM、分段 PCM 和模型输入。对同一条连续 PCM 比较字节数与摘要；对切分后的段则核对时间区间、拼接关系和边界样本。模型可能含登记参考或 padding，不能拿整个模型输入直接与原始录音比较，必须按输入构造规则分解。

```bash
# 示例：对同格式、同范围的 PCM 核对字节数与摘要
wc -c capture.pcm received.pcm
shasum -a 256 capture.pcm received.pcm
cmp capture.pcm received.pcm
```

当服务接收音频完整，但模型输入缺少尾帧时，查缓冲区提交和收尾；当模型输入完整、模型原始输出缺字时，查识别质量与上下文；当原始事件包含完整文字、页面缺字时，查合并和渲染。摘要一致证明输入相同，不能证明文字正确。

一种有收益的思路是在可靠声学间隙处分段，减轻长上下文识别负担。但机械按固定秒数截断可能切开词组，重新识别也可能产生不同错误。上线标准应同时覆盖漏字、重复、边界词、角色归属和长会话；一次样本恢复不能证明固定切分策略普遍有效。

## 极短尾段：不要把模型输入限制当作网络故障

角色区间拆分可能产生很短的边缘残片。波形本身存在，但长度不足以满足特征提取的窗口、步长或 padding 规则，推理服务因此报错。外层看到 HTTP 失败，不代表网络不可达。

处理步骤是回读失败段的采样率、样本数、来源区间和特征提取异常。先判断这个残片是否应独立成为一句话；若它只是核心区间的边缘，优先依据时间连续性和角色证据并入相邻核心。无法安全合并时保留未知状态或按契约失败，不能把两个角色混成一个输入。

padding 可以满足模型形状要求，但不能改变原始区间。补零只属于模型输入，不应进入 VAD、角色历史或输出时间轴。模型最小输入长度是具体模型和前处理的约束，不存在通用的“短于某个毫秒数就丢弃”规则。

## 首句角色未知：检查身份建立过程

首句尚无历史参考，重叠判断和声纹提取更容易不确定。强制把第一个匿名槽位映射为角色一，会让协议字段看起来正常，却污染后续身份历史。同一个说话人再次出现时，也可能被错误映射为新身份。

应分别核对活动区间、可用的单人参考、匹配候选和历史更新条件。测试不仅检查有几个人，还检查谁在什么时候说话、首次出现与再次返回是否一致、重叠区是否错误合并。

| 场景 | 必须保持的性质 |
| --- | --- |
| 同一人再次发言 | 有合格证据时复用已有身份 |
| 两人重叠 | 不因局部相似强行合并身份 |
| 极短新声音 | 证据不足时不污染已有原型 |
| 历史上下文重建 | 保留身份关联，重新核对匿名槽位 |

缩短窗口、裁剪角色数量或放宽相似度阈值都可能改善一个例子，但也会让真实双人被误合。修复要有反例集，包含相似音色、短插话、重叠和跨窗返回；角色编号连续只是展示性质。

## 断连：先确认请求是否到达

客户端的 WebSocket 状态在重连期间可能已经过期：旧连接仍被视为 open，新请求写入旧对象，服务端没有收到启动帧。服务端直连成功能排除部分服务故障，但不能证明应用的重连逻辑正确。

将一次连接尝试绑定到 generation，记录创建、open、首帧、close 和重连时间。回调执行前检查它是否仍属于当前代际；旧连接的 open/close 回调不能覆盖新连接状态。服务端按会话标识核对首帧是否到达，客户端按实际 send 记录核对发送目标。

没有请求到达证据时，保留“未定位”状态。需要同一次失败的双方时间线，不能把另一条成功 trace 当作失败问题的解决证据。

## 固定失败到可复现用例

每次复盘产出一个最小用例：输入摘要、首帧参数、发送节奏、期望事件和断言。传输、模型和 UI 可以分别回放，最终还要跑真实入口，确认修复进入了实际服务。

对照只改变一个假设，例如尾部提交方式或结果合并方式。无效策略也记录触发场景和退化原因，避免后来重复采用。问题关闭应同时满足原用例不再失败、相关反例不退化、部署工件确实包含修复。
