# AI 工程化

AI 工程化负责把实验中的模型能力变成长期稳定的服务。它覆盖数据、训练、模型注册、部署、评估、监控、成本、安全和反馈闭环。

![AI 生产工程生命周期](/ai/ai-engineering-lifecycle.svg)

## 从实验到生产的差距

实验通常只证明“某个样例能工作”，生产系统还要回答：

- 不同用户、边界输入和高峰流量下是否稳定？
- 数据、模型和 Prompt 变化后怎样回归？
- 结果错误时能否定位到具体阶段？
- 权限、隐私和写操作如何控制？
- 延迟、吞吐和成本是否满足业务预算？
- 失败后如何降级、回滚和人工接管？

## 用一次政策更新理解生命周期

退款助手原来依据政策 v3 回答“审核通过后 3–5 个工作日到账”，新政策 v4 对特定渠道改成 1–3 个工作日。仅替换文档不够：索引可能仍是 v3，答案缓存可能还保存旧回答，Prompt 也可能把旧天数写成了固定示例。发布单位应包含文档、索引、Prompt、模型接口、工具和权限配置，而不只是代码提交。

候选版本先在隔离索引中验证：新渠道命中 v4，其他渠道保留原条件，无依据时拒答，不同身份不能串读。通过后切少量真实流量，按版本统计错误、延迟和成本。若出现错误承诺，路由切回完整旧配置，并使相关缓存失效；线上已发生的退款动作需要单独核对，切回模型不会撤销业务交易。

大模型应用不一定自己训练模型，但 Prompt、RAG 索引、工具 schema 和评估集同样要经历版本、测试、部署和回滚。线上反馈应经过授权、脱敏与质量筛选后进入新一轮评估，不能直接覆盖当前测试集或自动训练。
