# Clash Verge 客户端

本页以 Clash Verge Rev 和其使用的 Mihomo 内核为例。Clash Verge 是界面，负责配置导入和代理开关；Mihomo 负责监听端口、执行规则与连接远端。名称相近的旧版或其他分支不能仅凭界面外观认定字段完全兼容，安装后记录应用与内核版本。

从 Clash Verge Rev 官方项目发布入口安装与系统架构匹配的版本，再确认内核正常启动。以下示例是本地 Trojan over TLS 的最小验证配置，不依赖前文尚未生成的订阅文件。

## 最小客户端配置

将以下内容作为 `client.yaml` 的完整起点，替换节点地址、端口、TLS 名称和随机密码。示例仅开启本机端口、仅验证 TCP，不开放局域网访问或管理 API。

```yaml
mixed-port: 7890
bind-address: 127.0.0.1
allow-lan: false
mode: rule
log-level: info

proxies:
  - name: proxy-trojan-a
    type: trojan
    server: proxy.example.com
    port: 443
    password: REPLACE_WITH_SERVER_PASSWORD
    sni: proxy.example.com
    skip-cert-verify: false
    udp: false

proxy-groups:
  - name: PROXY
    type: select
    proxies:
      - proxy-trojan-a
      - DIRECT

rules:
  - DOMAIN-SUFFIX,internal.example,DIRECT
  - MATCH,PROXY
```

`server` 是连接地址，可以与证书名称不同；`sni` 是本例使用的 TLS 名称，应由证书覆盖并保持校验开启。Docker 将宿主 8443 映射至容器 443 时，这里的 `port` 要填 8443。`DIRECT` 规则不负责配置企业 DNS：`repo.internal.example` 仍需由当前系统或已有 DNS 策略正确解析，才能通过内网访问。

这份配置没有 `AUTO` 组，也没有启用 TUN。先以最少变量验证节点，业务通过后再扩展规则、DNS 或自动切换。不要为绕过配置错误直接关闭证书验证。

## 导入与首次验收

在配置页导入本地 YAML，选为当前配置，再进入代理组 `PROXY` 选中 `proxy-trojan-a`。确认内核运行且监听 7890，保持规则模式，然后用显式代理访问可控 HTTPS 目标：

```bash
curl --proxy http://127.0.0.1:7890 --noproxy '' \
  --connect-timeout 5 --max-time 20 -I https://example.com/
```

本机 HTTP 代理通过 CONNECT 承载目标 TLS 字节，curl 仍验证目标证书。若目标不支持 HEAD，改用已知可读请求；401 应检查业务凭据，405 应检查请求方法，不能一律归因于代理。测试时在连接页或日志里核对时间、目标、命中规则和实际节点，避免浏览器缓存掩盖结果。

![客户端规则决策与直连代理路径](/network-proxy/data-plane-flow.svg)

显式测试通过后再开启系统代理，用浏览器和实际开发工具重复访问。命令行工具对系统代理、环境变量的支持各不相同；先显式指定能排除这些差异。没有连接记录时，先清空连接页过滤条件、发起新的持续请求并看日志，再判断是否未接入内核；已经结束的短连接不一定仍显示在列表中。

## 模式与流量接入

| 设置 | 影响范围 | 使用时的边界 |
| --- | --- | --- |
| 规则模式 | 已进入内核的流量按规则选出口 | 更具体的规则在前，兜底规则在最后 |
| 全局模式 | 已进入内核的代理流量走全局选择 | 应用没接入内核时，切全局也不会接管 |
| 直连模式 | 已进入内核的流量按直连方式出站 | 不等于应用绕过本机内核或关闭系统代理 |
| 系统代理 | 向操作系统登记本机代理地址 | 只影响遵守该设置的应用 |
| TUN | 按路由和内核支持接管网络流量 | 会影响 DNS、企业 VPN 与其他虚拟网卡 |

例如浏览器可用而下载工具没有记录，先查看下载工具是否支持 HTTP/SOCKS 代理，给它配置本机端口；确实需要透明接入时再评估 TUN。企业 VPN 已接管内网时，应保留企业 DNS 与内网路由，并为远端代理地址保留正确出口，避免回环。开启 TUN 后也要重新验证内网访问和系统 DNS。

## 订阅与自动策略

本地验证稳定后可改为私有 HTTPS 订阅。带 token 的 URL 和 YAML 都属于凭据材料，不能放入公开仓库、聊天截图或公共 CDN 缓存。更新时确认返回的是正确配置，先检查节点和组引用，再应用；节点重命名后，组里引用的名称也要同步。

| 代理组 | 选择方式 | 不能据此保证 |
| --- | --- | --- |
| `select` | 手动选择候选项 | 节点自动恢复或切换 |
| `url-test` | 根据指定探测目标测量选取 | 真实上传 API 也具有相同表现 |
| `fallback` | 按候选顺序选择探测可用项 | 正在传输的请求无损迁移 |
| `load-balance` | 按策略分配连接 | 多节点的字节量严格均衡 |

自动探测只覆盖指定目标与超时条件。下载、长连接和上传还要分别验收；切节点通常影响后续连接，已有请求是否中断取决于具体配置，不能把切换当成业务重试。

## 失败定位

导入失败时先检查 YAML 缩进、节点名引用和实际内核支持；订阅拉取成功但配置未应用，应看配置校验与运行日志。节点存在却握手失败，依次核对地址、发布端口、信任链与 TLS 名称；TLS 通过但认证失败，再核对密码与协议。

若全局模式成功、规则模式失败，比较同一请求的命中规则和 DNS 结果。若只有一个应用失败，对比它与显式 curl 的接入方式和实际请求目标。每次保留测试时间与错误信息，只改一个变量，然后沿相同请求复验；服务端排查见 [运维与排查](./operations.md)。
