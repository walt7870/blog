# 综合项目案例

项目练习应包含正常路径、失败注入与验收证据。下面五个方案是工程练习模型，不代表已经量产的产品；从采样到联网、控制、升级和能耗逐步增加约束，具体驱动与工具入口链接到对应机制页。

![采样节点与网关的数据和控制路径](/embedded/project-node-gateway.svg)

## 环境监测站：先证明数据可信

用 MCU、BME280、显示模块和串口构建采集站。先明确模块实际采用 I2C 还是 SPI，SSD1306 等控制器对应的成品模块接口并不统一。BME280 需完成配置与校准补偿，ADC 光照分压只表示相关电压，未经标定不能直接当 lux。

采样任务每 2 s 更新 `{sequence, sampled_at, value, validity}`，显示每 500 ms 读取最近快照，串口每 5 s 上报。读失败时保留最后一次有效值及其年龄，界面显示失效状态，不能把失败返回的 0 当作正常温度。拔掉传感器、卡住总线并恢复，验证超时不会阻塞显示和通信。机制见[外设驱动](./peripherals.md)。

## 智能网关：离线与重复命令

网关用 BLE 接入传感器、Wi-Fi/MQTT 上云，采集队列与发布队列解耦。云端不可用时，按条数、字节和时间限制缓存；存储满时明确丢弃旧采样还是停止采集。数据带设备身份和采样序号，平台可识别重复和缺口。

下行控制使用 `command_id`，设备验证权限和参数后执行，报告“已接受/已完成/失败/结果未知”。网络超时重试同一命令不能再次开阀；重要动作的去重状态需与实际执行恢复策略一起设计。测试 broker 断开、重复投递、设备执行后断电和重启恢复，不能只验证首次连接。协议边界见[通信协议](./communication.md)。

## 无人小车：控制周期与失效保护

编码器测速、速度控制与电机驱动构成闭环，遥控和避障改变目标值。PID 积分要乘采样间隔，微分要除采样间隔，还需输出限幅、抗积分饱和和噪声处理；不带 `dt` 的公式隐含固定采样周期，换周期后参数含义会变化。

初学可以先做 PI。下面为单方向速度控制的纯逻辑示例，假设输入为有限数、`dt>0`、`lower<upper`；饱和时仅允许积分向退出饱和的方向推进。

```c
#include <math.h>

typedef struct { double kp, ki, integral; } PI;

double pi_step(PI *p, double error, double dt, double lower, double upper) {
    double proposed = p->integral + p->ki * error * dt;
    double raw = p->kp * error + proposed;
    if ((raw >= lower && raw <= upper) ||
        (raw > upper && error < 0) || (raw < lower && error > 0)) {
        p->integral = proposed;
    }
    return fmin(upper, fmax(lower, p->kp * error + p->integral));
}
```

实际控制器在调用前校验传感器、时间间隔和参数，处理速度/电流限制与方向切换。先架空轮子、限流低速验证，再做场地测试；遥控丢失、编码器失效和控制任务超期时进入定义好的停止状态。看门狗不能代替硬件急停和电机保护。

## OTA：完整性、真实性与恢复是三件事

CRC/SHA 可以发现内容变化，但没有可信签名或认证不能证明固件来源。OTA 还需要目标型号、版本策略、长度上限、可信公钥/信任链以及可靠启动选择。优先采用目标平台支持的成熟升级框架，裸 Cortex-M 可评估 MCUboot，ESP-IDF 可使用其 OTA/回滚机制，并核对具体配置。

![候选固件从写入到试启动和确认](/embedded/ota-confirmation-states.svg)

分区必须对齐真实擦除单元。以 1 MiB STM32F407 的扇区布局为例，前四个扇区各 16 KiB、其后一个 64 KiB、再后七个各 128 KiB。旧式任意切成两个 448 KiB 槽会跨擦除边界，可能擦到邻区。

一种仅用于讨论容量的划分是：扇区 0–4 共 128 KiB 给 Bootloader/预留，5–7 共 384 KiB 为 A，8–10 共 384 KiB 为 B，11 共 128 KiB 为元数据/预留，结束地址 `0x08100000`。它不是可直接交付的升级布局：还需给映像头、签名、trailer、掉电记录和算法所需空间留量，384 KiB 槽不能装满 384 KiB 应用正文。

普通链接到 A 地址的固件不能简单跳到 B 执行。必须选择固定执行地址的 swap/copy 方案、分别链接的映像或被平台支持的重映射/位置无关方案。跳转也不只是改 MSP：中断、向量表、CPU 状态、外设与启动合同都要处理。不要在通用文章中复制两行强制跳转作为生产 Bootloader。

下载写入完成后验证，原子记录候选，试启动并在健康检查成功后确认；未确认复位则按算法回退。健康不只是进入 main，还应覆盖关键存储、外设与任务。首次启动会修改共享数据时，旧版回退必须仍能读取。验证下载中断电、元数据更新断电、试启动挂起、坏签名、错误型号、空间不足和失败回退，不以一次升级成功代替掉电验收。

## 低功耗节点：按电荷积分计算

假设每 900 s 采样发送一次，启动采集 50 ms×10 mA、发送 100 ms×120 mA，其余时间整板休眠 2 µA。这里的发送时间只是假设，不包含 LoRaWAN 入网、接收窗口与重传。单周期电荷和两年理想预算为：

```text
采集：10 mA × 0.05 s / 3600 ≈ 0.139 µAh
发送：120 mA × 0.1 s / 3600 ≈ 3.333 µAh
休眠：0.002 mA × 899.85 s / 3600 ≈ 0.500 µAh
合计：约 3.972 µAh / 周期，平均电流约 15.89 µA
两年：17520 h × 0.01589 mA ≈ 278.4 mAh
```

容量低于电池标称值不证明寿命达标，还需温度、老化、自放电、截止电压、稳压损耗、发射峰值和失败重试预算。用功耗分析仪或合适量程的采样设备测完整周期，检查仪表压降是否干扰系统；仅测稳态 µA 会漏掉无线峰值。将弱信号下的重传和重新入网计入，再用实测电荷更新预算。
