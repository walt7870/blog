# 实时操作系统

采样每 10 ms 必须推进，网络重连却可能等待数秒。RTOS 可以让通信任务阻塞等待、控制任务按优先级运行，但不会自动消除长临界区、优先级反转和过载。是否“实时”要用截止期与最坏响应来判断，内核名字和平均 CPU 占用都不足以证明。

![采样事件在 ISR、队列与任务之间流转](/embedded/rtos-event-flow.svg)

## 从任务边界设计调度

任务有自己的栈和调度状态，可以等待事件而不占用 CPU。以单核抢占式 FreeRTOS 为例，调度选择最高优先级的就绪任务；同优先级是否时间片轮转取决于配置，tick 也不固定为 1 ms。高优先级任务若一直就绪，低优先级任务仍会饥饿。

采集、控制、通信与日志按延迟要求划分，避免“所有通信最高优先级”。周期控制用绝对周期等待减少漂移，仍需记录超期并决定如何降级。裸机短任务和非阻塞状态机已能满足要求时，不必为使用 RTOS 增加共享状态。

上游 FreeRTOS `xTaskCreate` 的栈深度以 `StackType_t` 元素为单位；ESP-IDF 对应 API 通常按字节，不能跨平台抄 128 或 4096。任务与队列创建必须检查结果，堆和各任务栈还要计入中断、库函数与最坏调用路径。

## 事件通知与数据归属

| 原语 | 适合表达 | 容易误用 |
| --- | --- | --- |
| 队列 | 有界数据序列；通常按配置长度复制元素 | 队列复制指针不复制指向对象 |
| 任务通知/信号量 | 唤醒或按约定累计事件 | 二值通知会合并多次事件，不能当完整数据队列 |
| Mutex | 任务间共享资源互斥 | ISR 中不能取得 mutex；优先级继承不能解决全部死锁 |
| 事件组 | 若干状态位的组合条件 | 重复置同一位不会保存事件次数 |
| 软件定时器 | 定时安排短工作 | 回调阻塞会拖住同一服务任务中的其他定时器 |

下面是 ISR 投递一个值的机制片段：`samples` 必须在中断启用前创建，队列元素类型为 `uint16_t`，接收任务处理满队列策略和数据统计。它不包含外设状态清除。

```c
static QueueHandle_t samples;
static volatile uint32_t dropped_samples;

void sample_ready_from_isr(uint16_t sample) {
    BaseType_t wake = pdFALSE;
    if (xQueueSendFromISR(samples, &sample, &wake) != pdPASS) {
        ++dropped_samples;
    }
    portYIELD_FROM_ISR(wake);
}
```

此处假设该统计只有这个不可重入 ISR 写入，任务读取也要使用平台允许的同步方法；`volatile` 不能让一般多写者计数安全。`FromISR` 不是任何中断都能调用：例如 Cortex-M port 必须遵守系统调用中断优先级限制，检查实际实现的优先级位与配置，并启用断言。

## 临界区与共享外设

临界区必须短且不阻塞。它可能只屏蔽一部分中断；多核 port 还需处理跨核互斥，并不是统一“关闭全部中断”。高于屏蔽阈值的 ISR 若访问同一对象，临界区不一定提供保护。若把网络等待或串口输出包在临界区，会破坏延迟预算。

共享 SPI 时，锁覆盖片选到事务结束。异步 DMA 启动后立即解锁可能让另一个任务复用外设；应等待完成或由单一驱动任务管理请求队列。统一锁顺序、限制等待、规定超时后的外设归属，才能避免两个任务互相持锁等待。

## 用负载和故障验证设计

假设每 10 ms 产生一个采样，消费者可能连续 50 ms 无法运行，队列至少要覆盖这段积压及余量。但如果长期消费速度低于生产速度，增加队列只会推迟失败；需要限制生产、合并旧状态或升级处理能力。

同时记录队列峰值、任务延迟、丢样、锁等待与栈水位。上游 `uxTaskGetStackHighWaterMark` 返回的是历史最少剩余栈量，通常以栈元素计，不是最大已用字节；ESP-IDF 的单位要查对应文档。水位和溢出钩子仍不能证明所有执行路径安全。发生栈溢出后不宜继续复杂 `printf`，应按平台保存最小故障证据并进入受控恢复。

Tracealyzer 属于 Percepio，SEGGER 的对应工具是 SystemView；选工具时核对目标、授权和运行开销。故障注入至少覆盖消费者延迟、满队列、锁超时、内存分配失败与关键任务停止，观察看门狗是否真能识别失去进展。

## 内核与生态选择

FreeRTOS 适合已有驱动生态下的精简任务模型；RT-Thread、Zephyr 提供不同的设备与组件集成方式。比较时实际编译相同功能，测 RAM、Flash、启动与延迟，不能用一张固定“内核几 KB”表决定产品。安全功能、信息安全与功能安全认证也要分开：SafeRTOS 不是简单给 FreeRTOS 改名，Zephyr 有安全机制不等于具体产品已获功能安全认证，必须核对版本、证书范围和集成要求。
