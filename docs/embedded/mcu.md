# 微控制器原理与选型

环境节点需要两路 I2C、一路 UART 和电池供电。芯片参数写着“有三个 I2C”仍不一定可用：所选封装可能没引出全部引脚，复用功能可能与调试口冲突，DMA 通道也可能相互争用。选型必须从完整料号和实际连接表开始。

![微控制器内部的数据与时钟关系](/embedded/mcu-runtime-map.svg)

## 芯片类别与内核不是同一个维度

MCU 通常集成 CPU、片上存储和控制外设，适合裸机或 RTOS；MPU 通常面向更复杂的系统，可能集成大量外设并使用外部 DRAM，并非“只有 CPU”。SoC 描述片上系统的集成方式，与 MCU/MPU 概念可以重叠。Linux 也有无 MMU 的配置，但常见应用处理器平台使用 MMU。

| 内核或架构 | 需要核对的能力 | 示例 |
| --- | --- | --- |
| Cortex-M0/M0+ | 指令、乘法、调试与中断实现 | STM32L0 使用 M0+ |
| Cortex-M3 | Thumb-2、故障与中断机制 | STM32F103 |
| Cortex-M4 | DSP 指令；FPU 是可选实现 | STM32F407 带单精度 FPU；nRF52810 是 M4 |
| Cortex-M7 | Cache、TCM、总线与 DMA 可达性 | STM32H743 |
| Cortex-M33 | 安全扩展与具体芯片安全配置 | STM32L5 |
| RISC-V | ISA 扩展、ABI、中断控制器与调试规范 | ESP32-C3 |

RISC-V 是开放指令集规范，不表示每个处理器 IP、SDK、无线栈和工具都免费或开源，也不能据此推导芯片必然更便宜。相同 ISA 不保证二进制兼容所有扩展组合，更不保证外设驱动兼容。

## 存储空间要看实际实现

Cortex-M 的架构地址区间只是分类，不表示整个代码区都装满 Flash。STM32F4 的应用 Flash 常从 `0x08000000` 开始，复位时 `0x00000000` 的映射还受启动配置影响。容量、擦除粒度、RAM 分区、保留区与启动 ROM 必须查具体器件。

固件不仅要“总 RAM 够”：DMA 能否访问某块 SRAM、栈是否放在合适区域、Cache 是否参与，都会影响正确性。Flash 写入还涉及擦写寿命、读写并发限制与掉电状态。`.text/.rodata/.data/.bss` 如何落到存储，见[C 编程](./c-programming.md)。

## 时钟配置要闭合到外设

以 STM32F407 的一种配置为例，外部 8 MHz 经 PLL 得到 SYSCLK 168 MHz，AHB 168 MHz、APB1 42 MHz、APB2 84 MHz；这不是整个 STM32 系列的固定值。配置还需满足供电、Flash wait state、总线和外设频率上限。

在该器件常见配置中，APB 预分频为 1 时定时器取 PCLK；不为 1 时，相关定时器时钟为 PCLK 的两倍。因此 APB1=42 MHz 不等于 TIM3=42 MHz。其他系列还有不同的时钟选择与倍频规则。排查波特率和 PWM 时，从实际时钟寄存器一路算到外设，必要时用 MCO 或输出波形测量。

## 中断与启动

Cortex-M 复位从启动映射获得初始 SP 和复位入口，启动文件初始化运行环境，再进入 `main`。向量表不必永远位于物理 Flash 起始地址，是否可重定位以及对齐要求取决于内核与芯片；Bootloader 必须与应用链接和中断设置一起设计。

NVIC 的数值越小通常表示更高紧迫度，但实现的优先级位数、分组和 RTOS API 可调用范围都要核对。ISR 只搬运必要数据、记录状态并通知任务，满队列和硬件错误也要处理。清标志的顺序按该外设手册执行，不能把所有状态寄存器都当作 W1C。共享数据的正确性见[RTOS](./rtos.md)。

## 功耗模式与选型验收

Sleep、Stop、Standby 的保留内容和唤醒源随系列变化；STM32F407 不能照搬其他系列的 Shutdown 表。整板功耗还包含稳压器、外设和引脚漏电。启动时间和休眠电流必须连同电压、温度、RAM 保留与唤醒源一起说明。

为候选芯片建立约束表：最大采样延迟、可用 RAM/Flash、完整引脚复用、DMA 冲突、工作温度、供电峰值、待机预算、升级空间与供货。阅读顺序为 Datasheet 确认规格，Reference Manual 查机制，Programming Manual 查内核，再查 Errata 和相关应用说明。用原型测量最坏负载，留出增长余量后再定型；主频更高不能直接证明实时性更好。
