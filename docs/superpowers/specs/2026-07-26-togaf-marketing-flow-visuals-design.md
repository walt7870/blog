# TOGAF 营销系统流程图优化设计

## 目标

优化《TOGAF 营销系统实践》现有七张 SVG。图示应帮助读者顺着业务动作理解输入、裁决、状态变化、异常分支与运行证据，不把正文重复排成卡片，也不引入完整 BPMN 的复杂符号。

## 设计原则

- 每张图只回答一种核心问题，使用与问题匹配的图形语法。
- 主路径使用实线，返回或反馈使用回路线，异步事实使用虚线，异常或拒绝路径使用醒目的暖色。
- 箭头旁标注动作或业务事实，不只标步骤编号。
- 关键分支写清触发条件和结果，例如“授权失效 → 拒绝触达”“预留超时 → 释放预算”。
- 画面保持横向阅读，不依赖悬停和动画；移动端沿局部容器横向滚动。
- 保持当前文章的克制配色和中文技术知识库风格，避免装饰性渐变、过密阴影和无语义图标。

## 七张图的表达方式

### 营销架构决策链

采用四层因果闭环：业务结果与护栏、业务能力、数据与应用责任、运行证据。运行证据回到业务假设，强调 TOGAF 不是线性建设步骤，而是可校准的决策循环。每层只保留关键产物和一项失败后果。

### 价值流与能力断点

采用横向泳道：上层为“策略到学习”的七阶段价值流，中层为每阶段必须形成的关键事实，下层为支撑能力及成熟度热力。用断点标记说明人群不可重现、权益不可对账、曝光不可信如何阻断后续阶段。

### 数据权威与应用边界

采用“事实 Owner—应用协作—分析消费”三层结构。权威系统对事实的写入使用实线，消费者读取使用虚线，明确标注 CDP 和度量平台不能反向修改会员、Consent、权益和订单事实。

### 实时营销决策

采用时序图，展示渠道、决策入口、身份与 Consent、特征与人群、规则裁决、权益账本、证据记录之间的交互。主链显示延迟预算；增加授权拒绝、数据过期降级、权益不足拒绝和渠道展示后异步曝光四条分支。

### 权益与预算账本

采用状态机。正常路径为预留、发放、核销、结算；异常路径覆盖预留过期释放、发放失败补偿、交易失败恢复和退款后的返还或回冲。底部保留预算与限量权益守恒式，并把幂等键、状态前置条件和对账放到转换护栏中。

### 实验、归因与反馈

采用双轨闭环：交易事实轨负责曝光、转化、退款，测量轨分别进行漏斗、触点归因和实验增量计算。归因结果只能反馈策略，不能反向修改订单事实；迟到事件和退款通过重算窗口修正分析结果。

### 迁移路线

采用阶段路线图。七个阶段分别显示接管对象、进入条件、对账指标、回退点和旧入口退出证据。通过责任接管比例表达从影子运行到单一写入口的变化，避免把迁移误解成单纯的系统上线计划。

## 文章配合

图示前后的正文只补充必要的读图说明：先说明图回答的问题，再解释主路径、关键分支和证据。正文已有详细表格不重复搬进图中；若图与表含义重叠，以图表达关系、以表保留精确定义。

## 验收标准

- 七张图的图形语法与各自问题匹配，不再都是卡片串联。
- 读者无需阅读正文即可指出主流程、至少一个异常分支和最终证据。
- SVG XML 合法，文字不越出容器或 `viewBox`，箭头不穿过文字。
- 1440px 桌面端可完整阅读；390px 移动端仅图示容器横向滚动，页面不产生整体横向溢出。
- 全部图片正常加载，浅色和深色主题下保持可辨识，浏览器控制台无新增错误。
- `git diff --check` 与 `npm run docs:build` 通过。
